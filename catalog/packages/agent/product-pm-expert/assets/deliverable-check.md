# 交付前出稿质量自检规范（Deliverable Check）

> 配套资产：产品经理专家在交付任何 PRD / 需求文档 / 方案文档前的统一自检规范（单一事实源），与 agent.md 出稿自检能力、SKILL.md 出稿自检章节保持一致，改其一必同步其余。
> 用途：真实需求交付与演练出稿均适用；自动化回归脚本 `_verify_deliverable.py` 按本规范对演练 PRD 执行结构完整性 + 规范符合性 + 场景专项三级自检。

## 一、自检原则

1. **交付前必检**：文档完稿、交付给用户前执行三级自检，不跳过。
2. **结构先于内容**：先保证 15 段结构完整，再检查规范符合性，最后做场景专项。
3. **按场景分级**：全场景必查项一律检查；资金底线三件套仅资金类场景必查（非资金类不强制，避免误报）。
4. **措辞以产物为准**：自动化断言锚点必须与产物真实措辞一致；不存在的锚点先修产物或调整断言，不放宽标准。
5. **合规底线**：原创撰写、不抄袭、不侵权、不踩红线，合规声明随文档交付。

## 二、一级：结构完整性（15 段全查）

| 段 | 标题锚点 |
|----|----------|
| 1 | 一、文档信息 |
| 2 | 二、背景与目标 |
| 3 | 三、名词与术语定义 |
| 4 | 四、需求范围 |
| 5 | 五、方案对比与选型说明 |
| 6 | 六、用户角色与使用场景 |
| 7 | 七、功能需求 |
| 8 | 八、非功能需求 |
| 9 | 九、业务流程与状态流转 |
| 10 | 十、数据与埋点需求 |
| 11 | 十一、权限与安全要求 |
| 12 | 十二、异常处理清单 |
| 13 | 十三、上线计划、依赖与上线后验证 |
| 14 | 十四、风险与遗留问题 |
| 15 | 十五、附录 |

## 三、二级：规范符合性（全场景必查）

| 检查项 | 锚点要求 | 说明 |
|--------|----------|------|
| 验收可测 | 含 Given / When / Then | 功能需求有可验证的验收标准，不写「速度快」类模糊词 |
| 指标口径 | 含「口径」 | 目标与成功指标带口径定义（含/不含、时间范围、去重方式） |
| 方案对比 | 含「方案对比」与推荐结论 | 至少 2 个方案对比 + 推荐理由 + 演进路径（触发条件） |
| 依赖分级 | 含「阻塞」与「并行」 | 依赖按阻塞（Blocker）/并行（Parallel）/可绕过（Workaround）三档分级 |
| 需求追踪 | 含「需求追踪矩阵」 | RTM 覆盖需求→设计→用例→状态 |
| 评审自查 | 含「评审自查」 | 附评审自查结果清单，逐项打勾 |
| 合规声明 | 含「合规声明」 | 原创与合规声明随文档交付 |

## 四、三级：场景专项

### 4.1 资金类场景（资金底线三件套，必查）

资金类判定：交易/支付/退款/订阅扣款/计量计费/资损相关场景（如电商下单、订阅续费、开放平台计量）。

| 检查项 | 锚点要求 |
|--------|----------|
| 幂等 | 含「幂等」（幂等键定义、重复请求处理） |
| 对账 | 含「对账」（对账流程、差异处理、留痕） |
| 资损监控 | 含「资损」（监控告警、责任触达、上下文可查） |

> 底线：三件套不可砍除、不可降级为「后续版本」。

### 4.2 场景专项检查清单（按场景引用）

- 开放平台 API：见 assets/scenario-templates.md 场景 7 专项检查清单（8 项）
- 数据合规：见 assets/scenario-templates.md 场景 8 专项检查清单（8 项）
- 国际化：见 assets/scenario-templates.md 场景 9 专项检查清单（8 项）
- 交易/资损类：见 agent.md 能力 6 交易/资损类专项检查清单（8 项）

## 五、自动化回归联动

- `_verify_deliverable.py`：对 `_deep_test` 下各场景终版 PRD 执行三级自检（15 段结构 + 7 项规范 + 资金类三件套），纳入一键回归
- 演练新场景出稿后：运行一键回归即自动覆盖该场景 PRD 的自检，无需人工逐项核对

## 六、使用示例（演练出稿）

以 PRD-07 订阅会员与续费体系 v1.2 为例：

- 一级：15 段标题齐全 ✅
- 二级：GWT 验收 ✅、口径 ✅、方案对比 + 演进路径 ✅、依赖三档（阻塞/并行）✅、RTM ✅、评审自查 ✅、合规声明 ✅
- 三级：资金类 → 幂等（FR-02/05）✅、对账（FR-10）✅、资损（FR-11）✅，三件套入版未砍 ✅

> 合规声明：本规范为产品工作方法沉淀，内容全部原创撰写，不抄袭、不侵权、不踩红线。
