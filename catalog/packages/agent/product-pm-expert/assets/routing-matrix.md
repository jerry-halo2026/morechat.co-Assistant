# 能力矩阵与用户问题路由（Routing Matrix）

> 配套资产：产品经理专家接单第一步的「输入信号 → 场景模板 + 专项清单 + 产出形态」路由规范（单一事实源），与 agent.md 能力矩阵小节、SKILL.md 路由章节保持一致，改其一必同步其余。
> 用途：用户提出需求后，先路由再开工——命中场景模板与必带清单，避免漏清单、选错模板；多信号命中时按优先级裁决。
> 回归联动：`_verify_routing.py` 用 10 份演练 PRD 的真实输入信号回测路由命中，纳入一键回归。

## 一、路由总则

1. **先路由后开工**：任何需求先做一次路由（识别信号 → 选模板 → 定清单 → 定产出形态），再进入澄清与撰写。
2. **资金优先**：命中资金类信号（支付/扣款/退款/订阅/续费/资损/计量计费）→ 按资金类处理，资金底线三件套（幂等+对账+资损监控）不可砍。
3. **合规次之**：命中合规信号（隐私/个人信息/个保法/GDPR/跨境/儿童数据）→ 必带数据合规专项 8 项。
4. **多信号裁决序**：资金/合规（硬底线）> 安全红线（未成年人/涉政/涉暴）> 业务主场景（取最强业务信号）> 附属清单（全部带上）。
5. **无信号兜底**：无明确信号 → 走通用 15 段 PRD 流程 + 澄清问题清单，不臆测场景。

## 六、多轮对话路由（带上下文信号消歧）

### 6.1 多轮路由原则

1. **信号累积**：每轮输入都并入信号集（不覆盖、只累积），场景候选按命中信号计数重算。
2. **置信度锁定**：场景命中信号 ≥1 即候选；候选唯一且含强信号（资金/合规）时锁定场景；候选并列或均弱时继续收集或反问（每次 ≤3 问）。
3. **只增不减**：已锁定的必带清单不因后续轮次降级；后续更强的信号只追加清单（如出海后追加合规 8 项）。
4. **歧义消解**：同一信号词属多场景时（如「限流」属开放平台 API 与 SaaS 配额），用上下文词消歧——命中「API/开发者/密钥/网关」→ 开放平台 API；命中「租户/席位/按量」→ SaaS 配额。
5. **修正留痕**：多轮中场景发生修正时，记录路由变更（原场景 → 新场景 + 触发信号），供复盘与一致性校验。

### 6.2 多轮路由流程

每轮输入 → 并入信号集 → 重算各场景命中计数 → 判定（锁定/继续/反问）→ 输出场景模板 + 必带清单 → 出稿自检。

### 6.3 多轮示例（回测基线）

| 用例 | 轮次 | 输入信号 | 路由结果 |
|------|------|----------|----------|
| MT-01 电商 | R1 | 「我们有个小程序想优化一下」 | 无信号 → 兜底通用流程 |
| | R2 | 「主要是下单和支付链路转化率低」 | 电商交易 + 资金信号（支付） |
| | R3 | 「退款流程也要一起做」 | 锁定：电商交易 + 交易/资损 8 项 + 资金三件套 |
| MT-02 订阅 | R1 | 「我们 SaaS 现在靠买断收费」 | 弱信号（SaaS）→ 继续收集 |
| | R2 | 「想上线订阅会员，自动续费」 | 锁定：订阅资金 + 资金三件套 |
| MT-03 出海合规 | R1 | 「我们要做出海 App，先支持英语日语」 | 国际化 |
