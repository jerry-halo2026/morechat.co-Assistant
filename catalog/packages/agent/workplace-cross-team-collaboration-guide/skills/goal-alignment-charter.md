# 目标对齐与协作章程

目标对不齐，分工表写得再细也会跑偏。先对齐一个共同目标，再写章程，章程缺项不往下走。

## 适用场景
三方对成功标准说法不一样；开会总在争优先级；项目目标写在文档里，但没人按它做事。

## 输入（按原话贴）
1. 项目要交付什么、截止时间原话。
2. 每个部门的诉求原话：要什么、怕什么、不能让步的是什么。
3. 已有的分歧原话：哪次会、哪句话、谁和谁意见不同。

## 步骤
1. **抄原话**：把各方诉求原话逐条列出，不改写、不合并。
2. **找共同点**：从原话里找三方都认的一句话，写成共同目标，不超过 30 字。
3. **写成功标准**：把“做好”改成可核查的完成标志，例如“检查清单有人负责、有人复核、按期完成”。
4. **定拍板人与复核人**：每个决策点只写一个拍板人；复核人不能是执行人本人。
5. **写同步与升级**：每周哪天、谁汇报、汇报什么；卡住几天找谁、找谁裁决。
6. **三方确认**：章程发给三方，各自按表核对自己的事项，确认无歧义再往下走。

## 协作章程表
| 项目 | 内容 | 填法 |
|---|---|---|
| 共同目标 | 一句话 | 三方都认，不超过 30 字 |
| 成功标准 | 完成标志 | 可核查，不是口号 |
| 拍板人 | 每决策点一人 | 只写一个人 |
| 执行人 | 每项一人 | 只写一个人 |
| 复核人 | 第三方 | 不是执行人本人 |
| 同步节奏 | 每周哪天、谁汇报 | 写清内容 |
| 升级路径 | 卡住几天找谁 | 写清裁决人 |

## 完整示例
原话：产品方说“按期上线最重要”，技术方说“接口不稳定不能上”，运营方说“清单没人负责没法执行”。
对齐后：共同目标为“按期上线，检查清单有人负责、有人复核”；成功标准为“上线前检查清单完成并经复核”；拍板人为项目负责人；执行人为运营负责人；复核人为产品负责人；同步为每周一次；升级为卡住超过约定天数找项目负责人裁决。时间与数字均为示例写法，以实际记录为准。

## 常见错误
| 错误 | 修法 |
|---|---|
| 目标写成口号 | 改成可核查的完成标志 |
| 拍板人写两个人 | 每决策点只写一个人 |
| 复核人就是执行人 | 换成第三方 |
| 章程缺同步与升级 | 补齐六项再往下走 |

## 检查清单
- [] 共同目标不超过 30 字，三方都认
- [] 成功标准可核查
- [] 拍板人每项只写一人，复核人不是执行人
- [] 同步节奏与升级路径齐全
- [] 章程已发三方确认，无歧义
