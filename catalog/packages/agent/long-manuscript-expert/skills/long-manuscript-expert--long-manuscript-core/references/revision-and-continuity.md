# 局部修订与便携接续（2026.11.5）

本文件把上一轮局部执行中真正需要的"原件保护 + 写前字节核对 + 同号只读查询 + 项目文件接续"能力，重构为可携带、平台无关的产品方法。它不继承任何深层历史目录、冻结快照、旧运行样例或开发私有绝对路径；既有验收历史保持原状，本文件不改写也不覆盖它。

## 一、三类修订分开

| 修订 | 何时递增 | 不改什么 |
| --- | --- | --- |
| 意图修订 `intent_revision` | 用户明确采纳新的目标、硬条件或范围 | 不因新材料或换形态自动递增 |
| 证据修订 `evidence_revision` | 新材料进入证据集、来源变化或口径修正 | 不因纯表达调整递增 |
| 组合修订 `composition_revision` | 换形态、页型、样式或图文组合 | 不改有效意图、证据或作者立场 |

"继续"只恢复原目标与未完成工作，不等于采纳此前建议。未采纳建议保持提案状态，不进入有效意图。表达换形态不采纳提案，不改研究目标。

## 二、局改的实际步骤

1. **读当前稿**：实际回读用户当前稿、最新指令和项目卡，不凭上一轮记忆推断。分别记录原件、用户手改、范围外章节和已确认判断。
2. **冻结基线**：记录本次选定源码与原件路径、完整字节摘要与大小、允许修改的章节/图表清单、必须保留文本。
3. **写前核对**：在真正写入前，对每一份选定源码与原件重新读取完整字节并比对基线摘要。任一变化即拒绝本次写入，给出差异项与唯一下一步，不静默重绑旧绑定、不覆盖用户手改。
4. **原子新建**：改稿写入新文件（新版本号或新操作号），使用排他创建；目标已存在即碰撞拒绝，不覆盖原件、旧稿或已有回执。
5. **范围内语义回源**：授权章节内仍回到原始字段、对象关系和反证核对；每项变化区分"新材料导致"与"复核发现原稿已有错误"。
6. **范围外待同步**：摘要、目录、结论、其它图表或附录若受影响但不在授权范围，只列入可见的"待同步"清单，不擅改，存在已知未同步项时不宣称全稿一致。
7. **写入回执**：每次成功写入记录操作号、基线摘要、目标相对路径、写入字节摘要、写前核对次数、实际写者来源、时间与最终状态。
8. **读回**：写入后实际重新读取目标文件，核对字节与关键内容；源文件、原件和手改再次核对未被改写。

## 三、平台无关的路径关系

判断一个文件是否属于当前项目范围，必须使用**规范化后的路径关系**，不能用字符串前缀拼接：Windows 常规路径用反斜杠，`str(root) + '/'` 的正斜杠前缀会漏判模块与实际写者注册，也可能把相邻的相似前缀误判为同一范围。

正确做法：把根路径与目标路径都解析为绝对路径并规范化大小写/分隔符语义，再用"是否为相对子路径"的判定（如 `Path.resolve()` + `is_relative_to()`），同时拒绝符号链接逃逸和绝对路径越界。写者来源同理：用规范化后的相对路径与完整字节摘要登记，不以字符串包含关系代替。

本包 `scripts/scoped_writer.py` 提供该能力的最小确定性实现（仅标准库）：写前全字节核对、排他原子新建、碰撞拒绝、同号只读查询、写入回执与读回。它是**新实现**，不声称与旧冻结执行逐字节等价。

## 四、便携接续卡

项目内一张简明接续卡，随项目文件走，不依赖云记忆、本地记忆或后台状态：

- 当前目标、读者、决定、范围与排除项；
- 当前稿相对路径与字节摘要；
- 意图/证据/组合三类修订号；
- 材料覆盖：实际读取、有效证据、被采用三层，以及已读/未读与不可读范围；
- 承重主张与各自证据/反证/条件；
- 成果清单：主稿、阅读呈现、底表、视觉、物料台账；
- 写入回执列表与失败/未知状态；
- 唯一下一步与停止条件。

新会话只从用户项目文件恢复：先核当前文件与来源是否变化，复用仍有效的读取与结果，只重做受影响步骤；没有上下文时说明具体缺失。接续不重放旧请求、不重跑已封存验收、不换号重做。

## 五、未知与只读查询

外部动作（提交、写入、远端策略）状态未知时，只按**原操作号 + 原摘要**做只读查询；查询本身不产生新写入、不新增操作号、不改目录或反馈状态。

- 未查到回执、摘要不符、仅有 pending 或时钟回退，一律保持 unknown；不重发、不换号重算、不重新登记。
- 重复读取同一回执不重复产出本地成果，也不重新执行已完成或结果未知的搜索、写出与反馈。
- 恢复决策不等于重做工作；保留原签发与到期，不刷新有效期，不跨进程复用单调时钟。
- 反馈资格独立于回执；服务或会话重启后的回执查询不恢复已失效的反馈资格。

## 六、能力边界

- 无文件工具时交付可直接复制的正文与便携接续卡，文件写出/读回保持未完成，不把对话内容称为已保存文件。
- 无 Python 运行时时由专家按本文件方法直接执行规则，不要求安装运行时；脚本不是能力前提。
- 原件、旧稿、用户手改、历史出处与已确认判断默认只读；不自动清理、迁移、删除或覆盖用户作品。
- 需要 PDF 时实际生成并渲染检查；Markdown 存在不等于 PDF 合格。宿主显示与本地渲染分别记录，未查看页不写目视通过。
