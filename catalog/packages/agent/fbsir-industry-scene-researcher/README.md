# 智能原生案例研究员

## 安装 / Installation

本包由 **morechat.co-Assistant** 内容仓分发，**通过 morechat.co-Assistant 目录导入**：

1. 在 morechat.co-Assistant 仓中取出 `catalog/packages/<kind>/<id>/`；
2. 该目录即包根目录，内含 `plugin.json`、`agents/`、`skills/`，整体作为包目录导入；
3. 导入后由平台注册 Agent / Squad 与技能，无需额外安装脚本或注册命令；
4. 头像不在仓内分发（`avatars/` 已移除），由产品端生成。

## 运行时适配 / Runtime notes

- 向用户提问：使用 dsh-tool-ask-user（ask_user_question）；运行时无该能力时，改为在任务评论中提问并等待。
- 交付产物：使用 dsh-tool-present 声明交付；在任务评论中作为附件提交。
- 多角色协作：创建平台小队（Squad）并由 leader 通过 @ 派发子任务。
- 工具声明键为 `allowed-tools-dsh`（Task → subagent，AskUserQuestion → ask_user_question）。


高创智库出品，候选版本2026.11.3。

面向真实业务问题搜索与核验可比案例，解释案例改变流程和价值的机制、证据强弱与适用条件，并形成案例比较、单案分析或可检验的试点草案。结果区分企业自述、原文事实、独立观察、推断、冲突和未知。

当前版本保留原专家ID、单Agent结构、品牌、头像、行业顾问分类、默认提示、三条快捷提示和Skill入口。新增业务问题驱动的有界查询、互补来源与反证、跨行业机制迁移、双侧未知/冲突/版本，以及首值后最多两条建议。未采纳建议不进入有效条件。

## 起步方式

- 给一句业务问题或探索方向，寻找同行、同机制或同条件案例。
- 给一个案例名、网页或材料，请求核验、反证和深析。
- 给多个方案或待借鉴做法，请求比较、迁移判断、SOP或验证设计。

默认先提供聊天首值；用户要求时生成Markdown、CSV或自包含HTML等成果并读回核对。复杂格式和多模态能力按当前morechat.co入口实际可用情况执行，未观察范围明确保留。

## 专业方法

当前专家先加载[研究核心Skill](skills/industry-scene-service-recording/SKILL.md)，按任务选搜索/原文、证据/冲突、机制/试点、企业条件、七维、多模态、大材料、交付/续接与双侧策略参考。关键主张可用轻量validateClaims核对，无需为短答填完整bundle；工具无法加载时按Agent内联底线继续可完成内容并保留未执行项。

新结构化研究记录使用research.bundle/v2和research.claims-lite/v1。已有research.bundle/v1可由只读归档视图阅读；需要把旧材料用于新结论时，必须重新核对相关来源、范围和失效状态，不自动改写旧文件。续接保护用户手改，只重核受影响观察、主张和派生物。

细分赛道使用独立本地`research.track-research/v1` sidecar，不改bundle或网络合同。智能硬件售后分诊、异常复核和端侧交互三卡均为合成方法示例；未知、冲突与手改保留，未采纳建议不改意图或约束，显式切换只使相关证据失效。赛道不关联群、二维码、上下游、在线资源或企微空间。

## 本地策略与隐私

包内包含独立确定性 `scripts/strategy-client.mjs`，仅在宿主已有现代Node运行环境且本轮选择联调时使用。正式默认仅连接 `https://api2.u3w.com/case-research`；`http://127.0.0.1:8767` 只在显式开发选择时使用。匿名、无注册，不接收任意URL或跳转。服务失败或没有运行时不妨碍原生研究。

请求只包含合同闭合类别、版本、预算、实际工具capabilities与任务内加盐摘要，不上传ResearchBrief、原话、证据原文、案例明细、具体约束或随机盐。响应需通过闭合绑定校验；策略只填既有研究步骤。反馈默认不上传，明确选择后只提交与已签发决定绑定的闭合计数。

## 运行边界

本包自包含专业方法，不依赖额外MCP、连接器、兄弟专家或常驻服务。历史账户、会员、画像与需求办理连接器不进入本候选日常研究路径，本候选未接入这些历史能力。许可证和权利边界见 `NOTICE.md`。

试点建议是决策草案，不表示已在企业执行或产生经营结果。本地源码/行为评审、物理ZIP、morechat.co宿主、平台审核、上架、企业采用和经营结果是不同证据层，任何较低层通过都不能自动证明较高层。

出品方与花名：高创智库。

1. 我们做【业务】，想解决【问题】。请找值得借鉴的智能原生案例，包含同业和跨行业思路，比较做法、成效依据与适用条件，建议先试哪一条。
2. 帮我看这份【资料或案例】：AI改了哪些环节，价值从哪里来，哪些说法还需核实？请核对原始依据、补充同类对照，整理成一页团队简报。
3. 我们想借鉴【案例或做法】，已有【条件】。哪些能借鉴，哪些要调整？请给小范围试点：步骤、分工、成本、验收指标和停止条件。
