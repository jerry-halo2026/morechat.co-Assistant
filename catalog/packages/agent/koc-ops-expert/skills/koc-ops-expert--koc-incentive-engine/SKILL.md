# KOC 激励引擎 · KOC Incentive Engine

用在 5R 飞轮的 **R3 激励关**。这一关决定的不是"这个月出多少篇"，而是**三个月后还有多少人在**。

这一关最反直觉，也最容易做错。大多数品牌的激励设计恰恰命中了心理学上伤害最大的那几种形式：
**排行榜按名次发现金、公开打分、只给现金、效果不好就砍激励。**

## 什么时候用

- 要设计 KOC 的等级/权益/奖金体系；
- KOC 活跃度掉了、核心 KOC 流失、"发钱也没人干"；
- 要定激励预算，或老板问"这钱花得值不值"；
- 已有一套激励机制，想先体检再优化。

## 标准用法

### 一、先体检，再设计

如果用户已经有激励机制，**第一件事是体检**，不要直接给新方案：

```bash
python3 scripts/incentive_calc.py checkup --json '{"mechanisms":{
  "leaderboard_cash": true, "public_ranking": true, "cash_only_top_tier": true,
  "recently_reduced": false, "verbal_feedback_sop": false, "surprise_reserved": false,
  "quota_pressure": true, "派单_not_选单": true }}' --text
```

输出「激励健康度」分数 + 命中的风险 + 每条的依据与修正动作。
体检依据是 Deci, Koestner & Ryan (1999) 对 128 项实验的元分析（*Psychological Bulletin* 125(6):627–668）：

| 机制 | 对内在动机的效应量 | 含义 |
|---|---|---|
| **按绩效分档发奖**（对没拿最高档的人） | **d ≈ −0.80**（剔除离群值 −0.88） | 全文最强的削弱效应，且伤的是大多数人 |
| 完成即给（达标即得） | d = −0.36 | 可用，但要配言语反馈对冲 |
| 参与即给 | d = −0.40 | 比达标即得更差 |
| **事先不承诺的惊喜奖励** | **d = 0.01** | 几乎无害，性价比最高 |
| **言语奖励 / 正向反馈** | **d = +0.33**（大学生子样本 +0.43，儿童样本不显著） | 唯一能**提升**内在动机的手段，且零成本 |
| 奖励撤销后 | 延迟测量：一周内 −0.49、一周以上 ≈−0.55 | **激励只能加不能减** |

### 二、定预算（由增量决定，不是拍比例）

```bash
python3 scripts/incentive_calc.py budget --json '{"baseline_notes":40,"target_notes":100,
  "value_per_note":300,"active_koc":120}' --text
```

逻辑：**激励预算上限 = 增量内容篇数 × 单篇内容价值 × 30%**。
`value_per_note` 有两种取法，二选一并写进报告：
① 外采一条同类内容的报价；② 该内容进素材银行后能替代掉的素材制作费。

### 三、设计分层与权益

按 `@references/incentive-design.md` 的五层结构与五类权益库设计。三条硬规矩：

1. **层数 3–5 层**，晋级门槛必须是**行为**（产出/质量/复投），不能是粉丝量；
2. **每一层至少有一项"钱买不到"的权益**，否则这层就只是打折卡；
3. **物质激励占比随层级上升而下降**，核心层给身份、权力、信息、成长。
   行业数据佐证：社群回报方式中公开认可占 67%，现金仅占 11%。

### 四、算激励 ROI

```bash
python3 scripts/incentive_calc.py roi --json '{"incentive_spend":12000,
  "baseline_notes":40,"after_notes":96,"value_per_note":300}' --text
```

**注意**：这里算的是内容产出的增量，不是销售增量。销售增量必须用对照组/专属码/时间断点单独测，
两者混在一个 ROI 里是最常见的汇报事故。

## 输出要求

- 分层表必须五列齐全：**层级 / 准入门槛 / 义务（产出配额）/ 权益 / 晋级与降级条件**；
- 每一项权益标注成本量级（极低/低/中/高），让用户知道钱花在哪；
- 激励方案必须附**体检结论**：这套设计避开了哪些坑、还剩哪些风险；
- 所有阈值标注为【经验值/待校准】，写明用什么数据校准。

## 禁止

- 不得设计**按名次分档发现金**的常设排行榜（这是伤害最大的形式）。
- 不得建议**削减已发放的激励额度**。要降成本就换形式，并配一次说明沟通。
- 不得把激励与**拉人头**挂钩（"推荐 N 人入池得奖金"）——这既有传销法律风险，也会引入大量无效账号。
  推荐机制只能奖励**被推荐人的真实内容产出**，且不得形成多级计酬。
- 不得设计要求 KOC **先付费/买货**才能入池或升级的机制（入门费风险）。
