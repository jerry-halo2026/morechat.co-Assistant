# KOC 作战报告 · 标准章节结构

这份文件规定报告里**必须回答什么问题**。区块类型和排版由渲染脚本负责，这里只管内容质量。

判断一章写得好不好，只有一个标准：**读的人看完能不能直接去干活**。

---

## 报告的三种形态

| 形态 | 触发场景 | 必备章节 | 可省略 |
|---|---|---|---|
| **完整方案型** | 从 0 搭 KOC 体系 | 全部 12 章 | — |
| **诊断型** | 已有 KOC 池但跑不动 | 1、2、3、9、10、11、12 + 断点专章 | 招募话术、货盘设计 |
| **单点深化型** | 只要激励方案 / 只要分销方案 | 1、2 + 对应专章 + 10、11、12 | 其余 |

**不要为了凑章节而写章节。** 用户只问激励，就不要塞一份招募渠道大全进去。

---

## 完整方案型的 12 章

### 01 决策摘要（必备）

第一屏必须回答四个问题，每个一句话：

1. **做不做、做多大** —— 例：「先做 120 人核心圈层池，不建议一上来铺 1000 人」
2. **要花多少钱** —— 首期投入、月度预算、构成
3. **多久见效、见什么效** —— 时间点 + 可验证的指标
4. **最大的风险是什么** —— 一句话，写清楚"什么情况下我建议你停"

配 4 个 KPI（`kpis`）：目标池规模、月度预算、预期月产出内容量、预期 ROI 或 GMV。
**每个 KPI 都要标注是"目标值"还是"现状值"。**

### 02 现状盘点（有数据才写）

- 现有 KOC / 私域 / 达人资产盘点：有多少人、活跃多少、月产出多少
- 用 `radar` 画 KOC 池健康度六维（规模/活跃/质量/转化/留存/成本），现状 vs 目标 + 红线
- 数据缺失的维度**明确写"无数据，需从 X 后台导出 Y 字段"**，不要猜一个数填上去

### 03 目标与分层设计

- 池子的目标规模与结构：`pyramid` 五层塔 + 每层人数目标
- 每层的**准入门槛 / 义务 / 权益 / 晋级条件 / 淘汰条件**（`table`，五列缺一不可）
- 为什么是这个结构：结合品类决策链路长短、内容形态、客单价说明

### 04 招募方案

- 六池渠道矩阵（`cards` 或 `table`）：每池的触达方式、预估人数、预估成本、优先级
- 招募漏斗（`funnel`）：触达 → 报名 → 通过 → 首篇 → 首单，每环节给目标转化率
- 筛选标准：FIT-6 评分卡的维度与及格线 + 一票否决项
- 招募物料：招募帖 / 私信话术 / 报名表字段（报名表字段要写全，可直接建表）

### 05 培育方案

- `steps` 画 7-14-30 三段陪跑：每步的时间、负责人、动作、验收标准
- 内容 Brief 模板（放正文，不要只说"要写 Brief"）
- 内容质检 rubric：几个维度、各自的判断标准、不合格怎么返修
- 选题库：给出至少 10 个可直接用的选题方向，按人群/场景/痛点分类

### 06 激励方案

- 三层激励结构（物质 / 成长 / 情感），每层列具体的激励项
- 成长阶梯（`ladder`）：每级的门槛与对应权益
- 预算分配（`donut`）与激励强度测算：单人月激励上限、总预算上限、ROI 测算
- **过度激励风险提示**：哪些动作会把内在动机挤出去

### 07 分销方案

- 分销链路（`flow`）：从内容到成交到结算的完整路径，每个节点写清楚用什么工具
- 佣金结构（`stack`）：售价里各方拿多少，**必须包含平台技术服务费**
- 货盘设计：引流款 / 利润款 / 形象款 / KOC 专供款的配比与定价逻辑
- 结算规则：结算周期、对账字段、发票与个税处理方式

### 08 90 天节奏（`gantt`）

- 四条线（招募/培育/激励/分销）的并行排期
- 每个阶段的**卡点指标**：达不到怎么办（改什么、复测窗口多长）
- 关键里程碑用 `markers` 标出

### 09 度量与复盘机制

- 指标字典：每个指标的定义、公式、数据来源、看板位置
- 周会 / 月会看什么：3 个数就够，不要列 20 个指标
- 归因方式：怎么证明 KOC 带来的是增量（对照组 / 专属码 / 时间断点）
- **三张台账表的字段清单**（KOC 台账 / 内容台账 / 结算台账），可直接建飞书多维表格

### 10 风险与合规红线（必备，不可省）

- `checklist` 列红线：每条写清楚**依据的法规或平台规则** + **落到动作上怎么做**
- 分销层级、广告标识、报备、税务、个人信息收集，五项必须逐一说明
- 出事预案：内容翻车 / KOC 带节奏 / 数据造假 / 断货 各自怎么处理

### 11 假设清单（必备，不可省）

一张表，三列：**假设项 / 我用的值 / 需要用户拿什么数据校准**。

所有在正文里被当成事实用过的数字，只要不是用户给的、也不是平台公开规则，都必须出现在这里。

### 12 未来 7 天行动清单（必备，不可省）

不超过 10 条，每条格式固定：**谁 · 在哪天前 · 做什么 · 做到什么算完成**。

例：`运营小 A · 8/22 前 · 从企微导出近 90 天复购客名单并按 FIT-6 打分 · 产出 ≥80 人候选池，评分表填完`

## 写作纪律

1. **数字必须带口径**：`（用户提供）`、`（平台公开规则，2026-08 整理）`、`（行业基准，需校准）` 三选一。
2. **禁止正确的废话**：删掉所有"要重视""要加强""要提升"开头的句子。
   写"提升内容质量"不如写"每篇按 CQS 五维打分（20 分制），低于 12 分返修一次，批次合格率目标 85%"。
3. **每个建议都能被验收**：说不出验收标准的建议，就是还没想清楚。
4. **敢说不做**：如果用户的品类不适合做 KOC（决策链路极长、极低频、强线下、客单价极低且毛利极薄），
   在决策摘要里直接说明，并给出替代路径。**不要因为用户想做就假装它能做。**
5. **语言与用户一致**：用户说中文就全中文，包括图表标签。
