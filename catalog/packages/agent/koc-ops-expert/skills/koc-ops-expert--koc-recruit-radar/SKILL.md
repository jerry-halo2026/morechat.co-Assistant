# KOC 招募雷达 · KOC Recruit Radar

用在 5R 飞轮的 **R1 招募关**。这一关的产出不是"招到了多少人"，而是**一个能被服务好的池子**。

两个最常见的错误，这个技能就是用来防它们的：

1. **在错的池子里挑人** —— 渠道不对时，筛选标准再严也只是在垃圾里挑；
2. **招得比带得动的多** —— 池子的真实上限是**人力**，不是预算。招 1000 人只有 1 个运营，结果是履约率先崩。

## 什么时候用

- 从 0 开始搭 KOC 池，要定渠道、定标准、定规模；
- 手上有一批候选人要筛、要排优先级；
- 怀疑某个账号数据造假；
- 要回答"这个月要拿 100 篇合格内容，得招多少人、花多少钱"。

## 参考资料（做方案前先读）

- `@references/six-pools.md` —— 六池渠道矩阵：每池的触达方式、话术、预期转化、成本、坑，
  以及各平台的合规招募通路与粉丝门槛。**定渠道前必读。**
- `@references/fit6-scorecard.md` —— FIT-6 六维评分卡的评分锚点、五条一票否决、
  反刷量信号阈值、投前 15 分钟审号 SOP、需要用户去哪个后台取哪些字段。**打分前必读。**

## 标准用法

### 一、先算池子该多大（别先招人）

```bash
python3 scripts/koc_fit.py pool --json '{"target_notes_per_month":100,
  "ops_headcount":1,"service_mode":"复投池"}' --text
```

**两种口径分开算，不能混用（差 5~10 倍）**：

| 口径 | 适用 | 公式 | 例：40 篇/月 |
|---|---|---|---|
| **A 任务驱动池** | 有寄样 + 任务 + 陪跑 | 目标篇数 ÷（月活率 25%~40% × 活跃者月产 1~2 篇） | **50 ~ 160 人** |
| **B 自然贡献池** | 无寄样、靠自发（Nielsen 90-9-1） | 目标篇数 ÷（重度贡献者 1%~2% × 月产 2~4 篇） | **500 ~ 2,000 人** |

**然后用人力校验**：一次性铺量 200–500 人/运营、复投池 80–150、深度陪跑 50–80（已有工具；纯手工按 0.6 折算）。
人力不够时的三个选项：加人 / 降目标 / 把服务模式降级并上工具。

### 二、反推招募漏斗（要触达多少人、花多少钱）

```bash
python3 scripts/koc_fit.py funnel --json '{"target_notes":100,"mode":"invite",
  "C_sample":53,"weeks":4}' --text
```

`mode` 三选一：`open` 公开招募 / `invite` 定向邀约 / `platform` 平台官方合作单。
三种方式的履约率差异很大（平台单最高、公开招募最低），**不要用同一套转化率去测算**。

### 三、选人：FIT-6 评分 + 反刷量体检

```bash
# 单人打分
python3 scripts/koc_fit.py score --json '{"name":"KOC-张三",
  "fit":{"score":21,"reason":"…"},"content":{"score":14,"reason":"…"},
  "audience":{"score":11,"reason":"…"},"conversion":{"score":8,"reason":"…"},
  "coop":{"score":8,"reason":"…"},"cost":{"score":7,"reason":"…"},
  "vetoes":{"fake_data":false,"risk_persona":false,"competitor":false,
            "no_disclosure":false,"prepay_trap":false}}' --text

# 批量排序 + 分层分布
python3 scripts/koc_fit.py rank --file /tmp/candidates.json --text

# 反刷量体检（互动结构比点赞数诚实）
python3 scripts/koc_fit.py audit --json '{"like":800,"comment":5,"collect":18,
  "read":22000,"fans":6200,"category":"功能型"}' --text
```

FIT-6 六维（满分 100）：人货匹配 25 / 内容力 20 / 粉丝质量 15 / 转化力 20 / 配合度 10 / 成本效率 10。
分层线：**≥80 直通带货位 / 65–79 主力内容位 / 50–64 体验官观察 / <50 不建议**。

**五条一票否决**（命中任意一条不看总分）：数据异常、人设风险、竞品绑定、拒绝报备与标注、高额前置买断且拒签履约条款。

> **反直觉但重要**：互动率**高于大盘 2–3 倍**的账号不要直接录用，要进人工深审 ——
> 刷量账号的互动率恰恰高于均值。只按互动率排序会系统性地把刷量号排到前面。

### 四、数据从哪里来（不要编）

需要真实数据时，明确告诉用户去哪个后台取哪些字段（清单见 `@references/fit6-scorecard.md`）。
三方工具（千瓜/蝉妈妈/新红/飞瓜/灰豚）的数字**全部是抽样估算**
（千瓜官方说明其粉丝活跃度抽样比例为 10%–70%，传播指数"不排除误差较大的情况"）：
**适合排序和粗筛，不适合做结算依据，也不适合作为对外承诺的数字。**

## 输出要求

- 渠道方案必须给出**每池的预估人数、预估成本、优先级和负责人**，不能只列渠道名；
- 招募物料要给**成品**：招募帖文案、私信话术、报名表字段清单（可直接建表）；
- 所有转化率标注为【经验值/待校准】，并写明"跑完首批 100 个样品后用自家实测值替换"；
- 打分必须给理由，理由里要有具体依据（数据、内容事实，或明确标注的假设）。

## 禁止

- 不得编造达人真实报价、粉丝画像、历史带货数据。没有就写"需从 X 后台取 Y 字段"。
- 不得建议购买账号数据、刷互动、买粉来"优化"任何一个维度。
- 不得在招募话术里承诺"包爆""保 X 万曝光"，也不得引导站外交易或让 KOC 隐瞒商业合作关系。
- 不得为了凑够池子规模而放宽一票否决项。**宁可池子小，不要池子脏** —— 一个骗样账号会重复得手。
