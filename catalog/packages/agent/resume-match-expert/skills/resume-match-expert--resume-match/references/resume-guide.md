# 求职与简历方法指南

深度解读脚本的匹配报告时，对照本指南，给用户讲清楚「差距意味着什么、该怎么改」。

## 1. JD 匹配度解读

| 匹配度 | 含义 | 建议 |
|--------|------|------|
| < 30% | 简历和岗位严重不匹配 | 要么补关键技能，要么换更匹配的岗位 |
| 30% ~ 60% | 有基础但差距明显 | 重点补齐「缺失技能」里最核心的几个 |
| 60% ~ 80% | 匹配良好，可投 | 优化简历表达，突出命中技能 |
| > 80% | 高度匹配 | 直接投，重点准备面试 |

**关键**：匹配度低不一定等于「你不合适」，可能是「你的简历没写出你会的」。先核对「缺失技能」里有没有你其实会但没写的——这才是最容易提升的部分。

## 2. ATS 原理与应对

大厂用 ATS（申请人追踪系统）在 HR 看到简历前先做**机器筛选**，主要看：

1. **关键词匹配**：JD 里的关键词（技能、证书、年限）在简历里出现的频率。关键词密度低 → 直接被过滤；
2. **模块完整性**：联系方式、教育、经历、技能这些标准模块是否齐全。缺模块 → 机器识别不了；
3. **格式**：图片、表格、复杂排版会导致 ATS 解析失败。

**应对**：
- 把 JD 的关键词（技能名）**原样**写进简历（不要用近义词）；
- 确保四大模块齐全；
- 用纯文本格式（md/txt）投递比花哨的 PDF 更安全。

## 3. 量化成果的方法

HR 最看重「你做了什么 + 效果如何」。空泛描述（「负责系统开发」）说服力远弱于量化描述（「负责用户系统开发，支撑日活 10 万，响应时间优化 40%」）。

量化公式：**动作 + 对象 + 数字 + 结果**

| 空泛 | 量化后 |
|------|--------|
| 负责后端开发 | 负责用户系统后端开发，支撑日活 10 万 |
| 参与订单优化 | 优化订单流程，将下单耗时从 3s 降至 0.5s |
| 维护数据库 | 维护 MySQL 数据库，处理日均 500 万次查询 |

## 4. 简历写作要点

- **一页为佳**（应届），最多两页（资深）；
- **每条经历用 STAR 法则**：情境(Situation)、任务(Task)、行动(Action)、结果(Result)；
- **技能按 JD 顺序排列**，把 JD 最看重的技能放最前；
- **数字优先**：能用数字就用数字，HR 对数字最敏感。

## 5. 常见简历错误

- 把「岗位职责」写成「岗位要求」（要写「我做了什么」，不写「要求我做什么」）；
- 技能列表太长太杂（和 JD 无关的技能是噪音）；
- 用模糊形容词（「优秀」「出色」「丰富」）而没有证据；
- 格式花哨（ATS 解析不了）。

---

## 解读输出格式

```
[匹配度] 脚本计算的匹配率
[差距] 缺失的关键技能（哪些是硬伤，哪些可以包装）
[量化] 哪些经历需要加数字
[ATS] 哪些点会卡机器筛选
[改写] 具体怎么改（给示例）
```
