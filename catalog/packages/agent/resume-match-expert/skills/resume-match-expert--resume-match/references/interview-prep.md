# 面试准备指南

本指南支撑「面试陪练」环节：从面试前准备、高频问题库、回答质量评估，到模拟面试操作规范和面试后复盘。使用时结合用户的简历和目标 JD，不脱离具体材料空谈。

## 1. 面试前准备清单

### 1.1 研究公司 / 岗位

- 公司：主营业务、融资/上市状态、核心产品、最近动态（官网 + 公众号 + 招聘页）；
- 岗位：把 JD 逐条拆开，标出「硬性要求」和「加分项」，对照自己的经历找对应点；
- 团队与面试本身：能查到就了解团队做什么、汇报给谁；线下面试提前 10 分钟到场，线上面试提前测好设备，带纸笔记录。

### 1.2 按岗位调整自我介绍

同一份经历，对不同岗位讲不同的重点。自我介绍不是背简历，是「用 1 分钟证明你和这个岗位匹配」。

| 岗位方向 | 自我介绍侧重 |
|---------|-------------|
| 研发 | 技术栈、系统规模、性能/稳定性指标 |
| 产品 | 用户洞察、需求决策、上线效果 |
| 运营 | 增长数据、活动效果、用户留存 |
| 设计 | 设计思路、业务目标、落地效果 |
| 数据 | 分析框架、业务影响、可复用方法论 |
| 市场 | 渠道、预算、ROI |
| 销售 | 客户开发、成单数据、客户关系与续约 |
| 财务 | 核算/分析能力、流程优化、合规 |
| HR | 招聘/绩效/组织项目、业务理解 |

### 1.3 盘点 3-5 个可复用的项目故事素材

把简历里最出彩的 3-5 段经历，各写成一张「故事卡」：

- 项目一句话：做了什么、服务谁、规模多大；
- STAR-L 完整版（见 2.2）；
- 可迁移点：这段经历还能回答哪些问题。比如「最难的点」「团队冲突」「主动改进」都可以从同一段经历里挖素材。

面试前把故事卡过一遍，比背 50 道题有用。

## 2. 高频问题库

**第一步先定「岗位能力画像」**：从 JD（优先）/ 岗位描述 / 简历里提炼该岗位 3-6 项核心能力（每条标注来源），列给用户确认。之后所有输出都以它为准：每道题标注对应哪条能力，对不上的题删掉；画像有、题没有的补一道；待补知识要么来自答不上来的题、要么对应画像里某条能力。**技能词典和本题库都只是加速器，画像（岗位真实要求）才是唯一标准。**

**题量说明**：本库每个方向的题通常只有 6-7 道；若目标是 8-12 道，用「JD 逐条转化 + 简历深挖 + WebSearch」补足，不要用无关题硬凑。

**出题前提：先锁定目标岗位方向。** 本库按岗位方向组织，使用时必须先确认用户本次的目标方向，销售岗只用销售题，开发岗只用开发题，两者绝不混用。

| 规则 | 要求 |
|------|------|
| 锁定依据 | 以用户本次要面试的岗位和 JD 为准；与用户过去的方向不一致时，一律以目标岗位为准 |
| 可追溯（重点） | 每道预测题都要**标注对应的岗位技能要求**（JD 的哪条要求 / 该方向哪项核心能力），并把标注写进题目清单；标注不出或对不上的题直接删掉 |
| 禁跨方向 | 销售岗不出算法、系统设计题；开发岗不出纯销售话术题。只有用户明确说「为转行做准备」时才切换到新方向 |
| 待补知识同规矩 | 待补知识只收两类：本场面试真实答不上来的题、锁定方向的核心能力清单；无关领域的知识一律不进清单 |
| 拿不准就问 | 方向不明确时先问用户，不默认按技术岗出题 |

**没有 JD 怎么办**：先主动向用户索要，并解释「JD 就是职位的招聘说明——**可以直接截屏发我（截图能识别）**，也可以复制文字或发链接」；同时说明价值——「有 JD 的话，题目直接对着岗位要求出，命中率更高」。暂时拿不到时先按锁定方向出通用题，拿到后按 JD 校准。

**题库没覆盖的行业怎么办**（如传统制造、医疗、教育、公职等细分行业）：不硬套其他行业的题，按顺序生成——
1. **JD 转化**：把 JD 的每条职责/要求转成问题（「负责设备维护」→「你以前怎么做设备维护和保养计划？」）；
2. **简历深挖**：用户简历里与岗位相关的经历按 STAR-L 追问；
3. **WebSearch 校准**：查「[行业/岗位] 面试 高频问题」补充，结合 JD 筛选，不照搬网上的通用答案；
4. **通用模块兜底**：自我介绍、行为面、HR 面、反问环节直接复用本库通用部分。

待补知识同理：只从「JD 硬性要求 + 本场答不上来的题 + 该行业通用能力」提炼（如制造业的精益生产、ISO9001、SPC 等，可用 WebSearch 补资料），禁止塞无关行业的知识。

### 2.1 自我介绍

**30 秒版（电梯版）**：我是谁 + 一句话经历 + 和这个岗位最相关的一个亮点。

**1 分钟版（标准版）**：我是谁 + 核心经历（2-3 段，每段一句话带结果）+ 为什么适合这个岗位 + 为什么想来。

框架：**过去（做了什么）→ 现在（擅长什么）→ 未来（为什么是这里）**

常见陷阱：

- 背简历：面试官手里就有，重复没有信息量；
- 超时：超过 2 分钟会被打断，印象分下降；
- 没有落点：讲完没说明「所以我适合这个岗位」。

### 2.2 项目与经历深挖（STAR-L）

STAR-L 是 STAR 的扩展，多一个 L（Learning，复盘）。回答项目类问题统一用它：

| 字母 | 含义 | 要讲清楚 |
|------|------|---------|
| S | Situation 情境 | 背景：什么业务、什么阶段、什么约束 |
| T | Task 任务 | 你被要求或自己设定的目标 |
| A | Action 行动 | 你具体做了什么（动词 + 方法） |
| R | Result 结果 | 量化结果 + 对业务的影响 |
| L | Learning 复盘 | 你学到了什么、如果重来会怎么改 |

**追问预判**：面试官听完你的 STAR 后，几乎必问三个问题，提前备好：

1. **数据怎么来的**：指标口径是什么、谁统计的、有没有水分。答不上来，数字会被当成编的；
2. **最难的点是什么**：别只说「都挺顺利」。准备一个真实的难点 + 你的解法；
3. **如果重来你会怎么做**：考的是复盘能力，不是完美。承认不足 + 给出改进方案，比嘴硬加分。

### 2.3 行为面

行为面考「你过去怎么做事」，用来判断「你以后会怎么做事」。统一用 STAR-L 回答，每类问题给框架和陷阱。

| 题型 | 回答框架 | 常见陷阱 |
|------|---------|---------|
| 团队冲突 | 冲突是什么 → 你的立场 → 你怎么沟通 → 结果 → 你学到什么 | 只说对方错；回避说「没吵过架」 |
| 失败经历 | 目标 → 失败在哪 → 原因分析 → 补救/复盘 → 后续改进 | 把失败推给外部；选个无关痛痒的失败 |
| 主动改进 | 你发现了什么问题 → 为什么没人管 → 你做了什么 → 效果 | 把「领导安排」说成「主动」；改进没有结果 |
| 压力处理 | 压力来源 → 你怎么应对（方法） → 结果 → 沉淀的方法 | 只说「扛过来了」没有方法；抱怨环境 |
| 与上级意见不合 | 分歧点 → 你怎么论证 → 最终怎么决策 → 结果 | 说「领导永远对」或「我坚持己见」 |
| 同时多任务 | 优先级怎么排 → 依据 → 怎么协调 → 结果 | 说「加班硬扛」没有方法 |

### 2.4 技术 / 专业面

按角色给高频问题侧重。通用原则：**先讲结论，再讲过程；不会的题诚实说不会，但给出思路**。

| 角色 | 高频问题（各 6-7 个） |
|------|----------------------|
| 研发 | 1. 讲一个最有代表性的项目，架构和难点；2. 线上故障排查流程；3. 慢查询定位与优化；4. 缓存与数据库一致性；5. 设计模式的使用场景；6. 代码 review 关注什么；7. 最近在学什么新技术 |
| 产品 | 1. 讲一个从 0 到 1 或大改版的产品，决策依据；2. 怎么判断需求该不该做；3. 数据不好看时怎么分析；4. 和研发/设计冲突怎么处理；5. 最失败的一个功能，为什么失败；6. 怎么定义产品的成功指标；7. 竞品分析怎么做、结论怎么落地 |
| 运营 | 1. 讲一个操盘的活动/增长案例，数据怎么样；2. 留存下降的排查思路；3. 怎么做用户分层和精细化运营；4. 内容/活动选题怎么来；5. 预算有限时怎么分配；6. 最失败的一次运营动作，复盘是什么；7. 怎么衡量运营效果 |
| 设计 | 1. 讲一个最有代表性的设计项目，从需求到落地；2. 设计怎么支撑业务目标（转化/留存）；3. 和产品/研发冲突怎么处理；4. 怎么做设计验证（可用性测试/数据）；5. 建立过设计规范吗，怎么落地；6. 最近关注什么设计趋势，怎么判断要不要用 |
| 数据 | 1. 讲一个通过数据分析推动业务决策的案例；2. 指标涨跌怎么归因；3. 做过哪些指标体系搭建或数据建模；4. 数据质量差时怎么处理；5. 常用分析框架（漏斗/留存/AB 测试）怎么用；6. 怎么向非技术同事讲清一个分析结论 |
| 市场 | 1. 讲一个操盘的营销案例，预算和 ROI；2. 怎么做渠道选择和投放优化；3. 品牌/内容营销怎么衡量效果；4. 预算砍半怎么调整策略；5. 最失败的 campaign，复盘是什么；6. 怎么做用户洞察和人群定位 |
| 销售 | 1. 讲一个从线索到成单的完整案例；2. 获客渠道有哪些、怎么开拓新客户；3. 客户说「太贵了」或「再考虑一下」怎么处理；4. 怎么维护老客户、推动续约和复购；5. 业绩指标怎么拆解、怎么保证完成；6. 讲一次丢单经历，复盘是什么；7. 怎么和产品/交付团队协作满足客户 |
| 生产制造 | 1. 讲一个你负责的生产线/工艺/设备改进案例；2. 怎么保证产品质量与良率（出现批次不良怎么处理）；3. 产能与交期冲突时怎么排产；4. 安全生产你做过哪些管理动作；5. 怎么推动降本增效（精益改善/自动化）；6. 和生产/质量/设备等部门意见冲突怎么协调；7. 你熟悉哪些行业标准与工具（如 ISO9001、5S、SPC、六西格玛） |
| 供应链/物流 | 1. 讲一个你优化供应链或库存的案例；2. 交期延误怎么处理；3. 供应商怎么评估、管理和淘汰；4. 库存周转怎么优化；5. 成本、质量、交期冲突时怎么权衡；6. 缺料/断供风险怎么应对 |
| 财务 | 1. 讲一个做过的财务分析/预算/核算项目；2. 怎么保证数据准确性和合规；3. 做过哪些流程优化，省了什么成本；4. 业务部门要超预算怎么处理；5. 熟悉哪些财务系统和工具；6. 怎么向非财务同事解释财务数据 |
| HR | 1. 讲一个主导的招聘/绩效/组织项目；2. 怎么判断候选人是否合适；3. 业务部门要人很急但招不到怎么办；4. 做过哪些员工关系/离职面谈案例；5. 怎么理解 HRBP 和业务的关系；6. 劳动法合规上踩过什么坑 |

### 2.5 HR 面

HR 面不是走过场，核心考三件事：**稳定性、匹配度、性价比**。原则：诚实、简短、不抱怨、不暴露底线。

| 问题 | 应对原则 | 示例方向 |
|------|---------|---------|
| 为什么离职 | 讲「追求」不讲「逃离」；不贬低前雇主 | 「希望做更核心的业务」而非「前公司太乱」 |
| 职业规划 | 和岗位挂钩，讲 1-3 年内的成长路径 | 「在 XX 方向深耕，成为能独立带项目的骨干」 |
| 薪资期望 | 给区间不给死数；先了解对方预算；不主动亮底线 | 「结合岗位和我的经验，期望在 XX 到 XX」 |
| 稳定性（为什么选我们） | 具体理由 + 真诚，别背模板 | 业务方向、团队、成长空间，说一个真实的点 |
| 空窗期/频繁跳槽 | 提前准备，讲清楚原因和这段时间做了什么 | 学习、项目、思考，别含糊 |

### 2.6 压力面与刁难题型

压力面考的不是答案，是**你在压力下的反应**。原则：不卑不亢，不慌不怼。

- 被质疑「你经验不够」：不辩解，接住再转。「您说得对，我在 XX 上确实经验少，但我做过 XX，而且我学得快，可以举例说明」；
- 被连续追问到答不上：承认 + 给思路。「这块我确实没深入过，如果让我做，我会先 XX 再 XX」；
- 被问「你最大的缺点」：说真实的、可改进的、不影响核心岗位的缺点，并给出改进动作；
- 被故意打断/冷场：保持节奏，不慌，把话说完；
- 被问「如果给你降薪你来吗」：不急着答应，也不当场拒绝，说需要考虑，回去综合评估。

### 2.7 反问环节

面试官问「你有什么想问的」，是加分环节，不是客套。分场景给优质反问：

| 场景 | 优质反问 |
|------|---------|
| 业务/团队 | 这个岗位未来半年最重要的目标是什么？ |
| 业务/团队 | 团队现在最大的挑战是什么？ |
| 成长 | 这个岗位的成长路径是怎样的？ |
| 工作方式 | 团队怎么协作，和哪些部门配合最多？ |
| 面试官视角 | 您觉得做好这个岗位，最关键的能力是什么？ |
| 收尾 | 基于今天的交流，您觉得我有哪些需要补足的地方？ |

**不要问**：

- 薪资福利细节（留给 HR 面或 offer 阶段）；
- 网上能查到的问题（「公司是做什么的」）；
- 暴露没做功课的问题；
- 一次问太多（2-3 个足够）。

## 3. 回答质量三要素

模拟面试的反馈，统一按三个维度给：

1. **结构（逻辑）**：有没有框架（STAR-L / 结论先行），逻辑是否连贯，有没有跑题；
2. **证据（数字与细节）**：有没有具体数字、场景、动作，还是空泛的形容词；
3. **表达（简洁有重点）**：是否简洁，重点是否突出，有没有口头禅、废话、超时。

评分建议：每维度 1-5 分，附一句「好在哪 / 差在哪 / 怎么改」。（这是对**表达**的点评，与脚本输出的简历匹配度/评分无关；脚本失败时同样可以给表达点评。）

## 4. 模拟面试操作规范

给 agent 的陪练方法论，逐条执行：

1. **一次一题**：每次只出一道题，等用户答完再出下一题，不连环轰炸；
2. **先锁方向，再基于简历和 JD 出题**：出题前按第 2 节「出题前提」锁定目标岗位方向（不确定就先问用户）；题目必须从该方向的题库、用户的简历和目标 JD 里长出来，不考通用题库里的题；
3. **开练前先对齐预期**：明确告诉用户——模拟中不直接给答案；**练完的复盘会给出本场问题和参考答案**，所以不用担心当场没答上就白练；
4. **支持全类型与轮次**：模拟面试不限于 HR 面，支持 HR 面 / 行为面 / 专业面 / 压力面 / 反问环节，以及按真实流程的「全真模拟」；**HR 面默认一轮 6 题**（HR 问题类型有限，6 题足够覆盖），其他类型一轮 6-10 题，支持用户自定义（如「只练反问」「一轮 10 题」）；
5. **按三要素反馈**：用户答完后，按「结构 / 证据 / 表达」三要素反馈，指出好在哪、差在哪、怎么改；**模拟中只反馈、不给示范答案**（参考答案一律留到复盘给，见第 6 节）；
6. **练习形式（降低打字负担）**：模拟通过文字对话进行，但用户不必打完整段落——推荐用**语音输入法**（口述转文字）作答，最接近真实面试；或**要点式作答**（只打关键词/短句，你组织成完整回答再反馈）；或**框架填空**（你先给 STAR-L 骨架，用户只填关键点）；或**口述自练**（用户离线口述，只回来汇报「顺不顺、卡在哪」，你给反馈和参考答案方向）。每题控制在 3-5 句或几个要点即可——练的是结构，不是打字速度。
7. **难度递进**：从自我介绍 → 项目深挖 → 行为面 → 压力面，逐步加难度。用户状态好就上强度，状态差就降难度；
8. **严禁替用户编造经历**：用户答不上来时，给引导（提示框架、问启发式问题），不给现成答案。用户说「你帮我编一个」时，明确拒绝并解释原因；
9. **模拟真实节奏**：提示用户控制时长（自我介绍 1 分钟、每题 2-3 分钟），必要时模拟打断和追问；
10. **结束给复盘**：一轮结束，输出本场复盘——题目清单（含**答不上来的原题**）+ 参考答案（知识类给标准答案，经历类 / 行为类只给 STAR-L 框架和从用户简历、档案里能挖到的素材点，绝不补全细节、不替用户编造经历）+ 三要素整体评价 + 待补知识（按本次面试方向过滤）+ 最该练的一个点。

## 5. 回答红线与补救话术

### 红线（说了就扣分）

- **不编造经历**：被追问细节会穿帮，穿帮比「不会」严重得多；
- **不贬低前雇主/前同事**：面试官会想「你以后也会这么说我们」；
- **不暴露致命短板**：主动暴露「我代码能力不行」「我抗压差」等于自断；
- **不空谈理论**：只讲方法论没有实例，等于没回答。

### 说错话后的补救

补救原则：**承认 → 修正 → 补证据**，不狡辩、不硬撑。

| 场景 | 补救示例 |
|------|---------|
| 说错数据/事实 | 「抱歉，我刚才说的数字不准确，我核实一下再回答。准确的是 XX」 |
| 答非所问 | 「不好意思，我理解偏了。您问的是 XX，我的看法是……」 |
| 被指出错误 | 「您说得对，这块我确实记错了，谢谢指正。正确的理解是……」 |
| 情绪失控/说重话 | 「刚才我有点激动，抱歉。我的意思是……」 |

补救的关键是**快**：当场修正，比事后解释可信得多。

## 6. 面试后复盘清单

每场面试结束后，趁记忆新鲜，按下面清单记录，写进 `面试准备-{公司}.md` 的「复盘记录」小节（结构：`## 复盘记录` + 逐题 `- 原题：… / 当时表现：… / 参考答案：…`，最后一句「最该练的一个点」）：

复盘四步：① 每道题先分类（知识类 / 经历类 / 行为类）；② 知识类 → 补标准答案；③ 经历类 / 行为类 → 只补框架和素材点，不补细节；④ 待补知识按本次面试方向过滤。

| 项目 | 记录内容 |
|------|---------|
| 被问的题目 | 逐题记下（尽量保留原话），标注答题表现（答得好/一般/卡壳/答不上来）+ 题目类型（知识类/经历类/行为类） |
| 答不上来的原题 | 把没答上或答得差的题单独拎出来，原题誊写准确，并记下当时卡在哪一步 |
| 参考答案 | 为每道答不上来的题补上答案：知识类题给标准答案或答题要点；经历类/行为类题只给 STAR-L 框架和从用户简历、求职档案里能挖到的素材点，绝不补全细节、不替用户编造经历 |
| 亮点 | 哪几个回答面试官明显感兴趣（追问了） |
| 失误 | 哪题答偏了、说错了、超时了 |
| 待补知识 | 从「答不上来的题」提炼知识盲区，并对照「岗位能力画像」的核心能力与该行业通用能力，列成学习清单（只收这三类，禁止塞无关行业知识） |
| 下次改进 | 挑 1-2 个最该改的点，下次面试前专项练 |

复盘不是写日记，是**为下一场面试做准备**：把「答不上来的原题 + 参考答案」整理进自己的题库（同类题下次直接会答），把「待补知识」排进学习计划。
