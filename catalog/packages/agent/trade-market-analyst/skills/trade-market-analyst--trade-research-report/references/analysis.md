# 六项分析与背调：O4 同源交付

采购商分析/多维分析（S29）、供应商分析/多维分析（S33）、市场分析/多维分析（S37）、国别分析/多维分析（S41）、AI背调/全面背调（S45）、AI背调/公司层面（S46）均属智能决策入口，采用 O4；默认聊天摘要、Word、Excel 证据表，显式格式优先。名称、入口、胶囊、71项目录顺序和完整提示词保持原文，编号仅供追踪。使用 get_playbook(scenario="buyer_deep_dive") 与 get_playbook(scenario="supplier_audit") 返回方法中的身份核对、贸易节奏和风险并列方法，按本次计划适用步骤执行；不自动增加邮箱、电话或联系人购买。

采购商多维分析（S29）请求固定带 `outputs.report_contracts: ["whole-report/3"]`：计划会多出原产国结构、供应商×品类交叉（HS 两位章）、主力单品三节，替代旧计划里"国家结构不可用"的占位节；不带则按旧计划规划。以上均为合成输入示意，不是客户数据或预算授权。公司或域名必填，国家可用于主体消歧，不能当贸易过滤条件。市场分析必填HS、国家角色与方向；country_role=partner 时另需显式 reporter，不默认中国。国别分析产品缺省全商品，方向仍必填。HS按文本保留前导零，不截短不支持精度。主体占位、未知国家、单日期、日期反向与不明确方向先确认。

删去可选数量、期间、规模、输出细项时恢复本任务完整输出、证据和限制，不退回仅一张表。除公司层面外默认执行日向前12个日历月；月趋势使用首尾实际月桶数，通常13桶，不能裁短。公司层面使用最新可用企业资料，不用贸易窗口裁剪登记、股权或原始财年。显式请求优先，默认格式 chat+docx+xlsx，不代表默认预算。

## 执行顺序与查询记录

先 `plan_report(task=...)`，问完待确认项；规划零费且无身份查询，不替用户批准后续付费。读取 task_context、pending_confirmations、steps、required_sections、coverage_scope、capability_hints、output_schema、checklist。付费前把计划步骤的 wallet_ceiling 合计成预计点数告诉用户（普通点、联系人点分开）；服务授权和余额以服务端为准，未知宿主公开检索费用不得写成免费。

按 SKILL.md 第 3 步写一份查询记录：每次付费调用记工具、参数、关键数字、服务端实扣和调用编号。续做时同参成功的调用不重跑；已发出未记结果的可能已扣费，先告诉用户。不用 `task_run.py` 的预约、派发、见证与收据，也不必逐笔保存完整原文；后面要引用明细的大响应可另存文件，在记录里写路径。

主体、覆盖与公开证据的方法不变：

- 身份：结合名称、官网、地址与注册国，从候选响应里明确选一行，记下调用编号、行号（从0起）、company_id 与注册名。不得自动用候选首行，不得把同名、别名、集团或子公司混为一体。buyer/supplier 逐角色记下贸易匹配名称与依据：候选的 name/name_native、用户明确确认的原名、所选完整画像的 international/native，或精确公开页面；不接受自由文字冒充名称依据。
- 覆盖：公司任务以能力查询结果和计划允许的完整兼容市场组为准，不能把单个注册国代替全球贸易范围。市场任务记下计划的报告国与覆盖年份，外国报告国未核实不能付费回落中国。未查组、被排除市场和年份缺口保留。
- 待确认项：blocking 字段要用户明确回答，缺项时重新规划；不能以建议代替用户答案。
- 公开证据：绑定所选主体与章节，记下无凭证的精确 URL、带时区的取得时间、精确摘录、字段与值，并区分抓取事实、用户陈述与推断。摘录必须确含所选主体，不能借另一企业的名字或正文冒认。合成例仅用保留域名，实际工作须用真实页面与真实获取时间。检索无发现另记检索范围与链接，只表明本次搜索范围未发现；未提供公开材料留待检索，不能判无风险。

未知费用标未知并告诉用户，不计零；失败调用的实扣照记，不能省略。

## 交付与重新渲染

每种格式取 `get_render_spec(format=..., output_profile="O4")`，按交付标准出成品，宿主原生文档、表格或网页能力均可；交付前按规范自检一遍。重渲染或换格式只用已取得的数据，另取新文件名，不覆盖既有成品，不重新付费取数。

采购商多维分析（S29，新版合同）要网页且已安装报告套件时，不调 `get_render_spec`、不手写网页：把计划存成工作目录的 `plan.json`，每个数据步骤的响应原文存成 `responses/<步骤编号>.json`（同一步骤查了多个市场组时存 `<步骤编号>.<序号>.json`），再运行已安装报告套件里的 `render_buyer_analysis.py`（参数 `--run <工作目录> --out <文件名>.html`）。它离线生成带品牌标识、图表库内联的单文件网页并自检，报错时把原话转告用户；没装报告套件时（本技能单独使用即属此情况）不要停下：告诉用户标准网页模板需要报告套件，再取 `get_render_spec(format="html", output_profile="O4")`，用宿主网页能力按已取得的数据生成网页，保留「数据来源与口径」一节并注明不是标准模板；用户也可改要聊天摘要、Word 或 Excel。

逐事实保留章节、主体、角色、指标、值、单位、期间、币种、财年、合并口径、状态、来源及证据编号。未知不补零，营收原财年/币种与海关金额分开。数量没有单位不得相加；角色与市场组分开，双向记录可能重叠。伙伴/品类Top-N不是全量分母，不能用排名之和称全商品结构或全球份额。G2企业国家结构只在新版合同（S29）由原产国章节按记录实际原产国给出，其余仍保留未覆盖章节；G3官方统计HS结构当前无直接能力。公开无发现不当无风险。

图表只引用已核验同主体、同单位、同口径保存点，缺月份不补零；范围、来源、数据截止与逐点证据须回读一致。字段缺失、未查询、成功未查到、无覆盖和失败分别保留，六项样例均展示部分成果，不能冒称完整分析。宿主公开检索费用未知独立披露。

## 七项单章：只执行选定章节

采购商分析/供应商分析（S30）、采购商分析/品类分析（S31）、供应商分析/供应商分析（S34，用户已批准供应商→采购商结构）、供应商分析/品类分析（S35）、市场分析/贸易伙伴分析（S38）、市场分析/价格分析（S39）、国别分析/贸易伙伴分析（S42）复用O4同源chat+docx+evidence_xlsx。仅这些单章，不能默认追加多维章节、完整画像、公开尽调、总量查询、前期、翻页或产品钻取。名称与原顺序保持；S34原冲突提示留历史，有效执行不再问已裁定的问题。

公司单章至少提供真实company；可选country/domain仅作身份消歧。默认按用户提供的名称查询：记下用户的明确确认，贸易名称只用该原名、只给本章角色（buyer或supplier）。不能添加企业编号、注册名称、候选行或伪造公司库证明。业务声明为“按用户提供名称查询，法律实体及同名关系未独立核实”。多抬头、OR或实际同名歧义先明确，不自动合并。明确需候选核对才复用上文已选的候选；仍不强制完整画像。

按本章角色与维度核对完整兼容市场组后，只调search_trade的supplier/buyer/category聚合。默认按保存计划的HS四位品类范围执行；明确其他HS层级优先。零售体系层级在当前公开能力响应无法核对时本章停止并标无覆盖，不偷换HS或手工分类一页当全量。角色、市场、日期、体系层级证据不符则不采用；注册国不限制交易市场。排名原值、实际度量、对手/品类原名、层级及最后交易日分别保留，同名行不自动合并。来源无数值总分母时份额/集中度/其他项未知，不用Top-N合计或meta.total条数替代；未有可比前期不推新出现、消失或变化。图表只展示返回结构的已知原值柱图，注明子集与真实证据，不画全量份额饼图。

统计伙伴source份额仅为本报告国/方向/产品/伙伴过滤范围返回值；数值总分母、剩余项和截断标志未提供，不能从四舍五入份额倒算grand，不能把meta.total的返回伙伴数当全伙伴总量。价格只保留来源返回的加权单位价值，数量单位未知、混合或缺失时不自行计算价格、不作不同HS物理单价比较；即便有单位价值也不是实际市场报价。量为零/缺失不填价，缺月份不补零、不插值。

普通点按实扣记账、不必事先确认预算；工具或参数要变更时重新规划。失败调用的实扣照记入查询记录。无数据仅严格计数零+范围证据成立时可交付已查范围零记录的局限报告；来源失败、计数未知、覆盖不符绝不称无采购。所有附表、正文、图表标题和Excel单元格用同一份核验过的数据，异常字段标缺项，独立合格字段仍可保留。
