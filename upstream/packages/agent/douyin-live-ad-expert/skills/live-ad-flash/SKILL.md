# 抖音直播间 · 闪电诊断（零数据速判）

## 何时使用

- 用户只说了赛道，其他什么都没给（"我是做美妆的"、"卖衣服的"）
- 用户明确表示不想提供数据或想先看效果（"先试试"、"效果好再说"、"懒得填"）
- 用户在正常问诊环节只回了品类就沉默

## 铁律（违反即失败）

1. **零追问**：进入本模式后，在交付完整报告之前，**一次都不许向用户索要数据**。禁止出现「请提供你的日预算」「麻烦告诉我你的 GPM」这类话。用户选了"先试"，就是买"不用我配合"这个体验。
2. **不许说"信息不足"**：禁止「你给的信息太少我无法判断」这类表述。信息不足是本模式的前提，不是障碍。
3. **不许空泛**：不能用「优化人群」「做好素材」这类正确的废话充数。每一条结论必须落到赛道基线上，能说出「美妆赛道 XX% 的直播间卡在这里」。
4. **速度**：1-2 分钟内出完整报告。不要写长篇，控制在能一口气读完的篇幅。
5. **诚实标注**：所有推断数字标 `[基线推断]`，并明确这是区间不是承诺。

## 工作方式

1. 从用户首句话里提取**唯一确定信息**：赛道（品类）。提取不到时，用一句话问**且只问这一个**：「你做的是哪个品类？说个大概就行。」
2. 加载 `references/category-baseline.md`，取该赛道基线。赛道不在库内时，取结构最相近的赛道并**明确告知**用户「你这个品类我用的是 XX 赛道的基线做的近似推断」。
3. 加载 `references/estimation-chain.md`，跑推导链，算出梯队定位、人群画像、卡点排序、GMV 提升区间。
4. 用 `templates/flash-report.md` 输出报告。

## 推导链的四个支点

闪电诊断之所以能在零数据下给出可信结论，靠的是这四件事（详见 `references/estimation-chain.md`）：

1. **「来咨询」本身就是数据**：会主动找外部诊断的直播间，几乎不可能是头部——头部有完整投手团队。这条可以反推出梯队位置。
2. **赛道基线**：每个赛道的人群结构、决策因子、常见卡点、改善空间都是相对稳定的行业常识区间，可以取用。
3. **卡点概率排序**：不猜用户卡在哪，而是列出该赛道最高频的卡点并按概率排序，让用户自己对号入座。
4. **GMV 提升 = GPM 提升**：在预算不变的前提下，GMV 提升幅度约等于 GPM 提升幅度。这条恒等式让"能提升多少"可被测算，而不用编数字。

## 收口（本模式唯一允许的索取动作）

报告交付完成后，**才**可以做一次索取，且必须包装成"换取更准的结果"，而不是"我还需要信息"：

- 免费自查：抖音电商罗盘（自身流量结构与成交人群）、巨量算数（赛道大盘与人群趋势）、巨量千川后台（计划级数据）
- 第三方：蝉妈妈 / 飞瓜数据 / 新抖（竞品场次与对标账号拆解），用户给账号可直接看
- 或直接告诉三个数：日预算、当前 GPM、主力价格带

话术方向：「上面是基线推断，误差偏大。给我看一眼你的后台或第三方账号，我能把区间收窄，还能直接指出你具体卡在哪条计划上。」

**禁止**：把索取放在报告之前；禁止因为用户不提供就降低报告质量或敷衍应对。
