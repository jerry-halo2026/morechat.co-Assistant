# 网页报告：默认交付

胶囊任务默认交付一份单文件网页报告（HTML），聊天摘要、Word、Excel 证据表作备选。网页由报告套件按固定版式画，你只写一份很短的 page.json：结论和要点。数字、名单、日期全部由套件直接从 data.json 取，你不抄写任何数字。

## 步骤

1. 请求与套件格式照旧：调 `plan_report` 与套件时格式仍按任务原来的 chat+xlsx（分析、背调类另加 docx），不向服务端要 html，也不为任务网页取 `get_render_spec` 的 html 规范。
2. 照常执行到 `prepare`，生成 data.json；`summary.deliverable` 为否时如实说明，不出网页。
3. 在运行目录写 `page.json`（格式见下），然后运行 `python <套件>/task_run.py --run <运行目录> html`，得到同目录的 `report.html`。命令只检查 page.json 的字段和档位，几秒钟完成，不再跑自检或对账。
4. 交付：先给 `report.html`，再一句话列出备选（聊天摘要 / Excel 证据表 / Word）；用户点名要备选格式才另出。命令报错时按提示改 page.json 再跑一次；没有套件或宿主不能运行命令时，交付聊天摘要并说明网页报告需要报告套件。

## page.json

所有版式都写 `"contract_version": "page/1"`；版式由任务自动决定，不用写。可选 `notes`：最多 5 条补充说明（每条一句话），会放进页面最后的「怎么算的」。

采购商 / 供应商分析、找客户名单及其他任务：

```json
{"contract_version": "page/1",
 "summary": {"one_line": "一家香港公司扛近三成，宁波一群互为备份",
             "action": "以小家电做第二供应商切入",
             "points": ["前 3 家供应商占 63.6%", "小家电 66% 押在一家", "华与华 5–6 月降了 46%"]}}
```

- `one_line` 一句话结论（60 字内），`action` 一个建议动作（40 字内，可省），`points` 最多 3 条要点（每条 80 字内）。要点里的数字必须能在 data.json 里找到。

骗子判断（只给结论和一句理由，不写建议、不列依据清单）：

```json
{"contract_version": "page/1",
 "verdicts": [{"tier": "大概率是骗子", "reason": "真实老公司被冒用，网站两个月前才注册，还要求打款到个人账户。"},
              {"tier": "不建议跟进", "reason": "判定为骗子，不再评价值。"}],
 "inputs": [{"field": "网址", "value": "www.lumen-trading-example.co", "clarity": "看不清", "note": "末尾有污渍，.co 和 .cl 都查了"}]}
```

- 第一条「是不是骗子」只能选：大概率是骗子 / 高度可疑 / 有疑点，需核实 / 未发现骗子迹象 / 资料不足，补X即可判断（写明缺哪一项）。
- 第二条「值不值得跟」可省，只能选：高价值 / 中价值 / 低价值 / 不建议跟进 / 资料不足，补X即可判断。
- `reason` 一句话（120 字内），用大白话。`inputs` 是从名片、邮件读到的信息（最多 12 行），`clarity` 写「清楚」或「看不清」。

负面清单（S48：一个总体结论 + 五类各给高中低）：

```json
{"contract_version": "page/1",
 "verdicts": [{"tier": "有轻微负面，可正常合作", "reason": "只查到一条已撤回的指控，没有判决、处罚或拖欠货款。", "action": "正常推进", "points": ["一条指控已撤回"]}],
 "categories": {"recall": {"risk": "低", "summary": "没查到召回", "searched": "查了美国 CPSC、欧盟 Safety Gate"},
                "reviews": {"risk": "中", "summary": "漏水", "items": [{"text": "杯盖漏水", "where": "亚马逊差评前三", "opportunity": "给双密封圈方案"}]},
                "litigation": {"risk": "低", "summary": "一条指控已撤回", "items": [{"text": "被指控描述不实", "state": "已确认", "evidence": "<data.json 里的证据编号>"}], "impact": "撤回了，不算数"},
                "finance": {"risk": "中", "summary": "财务资料不全", "items": [{"text": "没有营收利润", "state": "还没核实"}]},
                "media": {"risk": "低", "summary": "没查到负面报道"}},
 "excluded": ["同名公司的罚款——国家不同，不是这家。"],
 "change_conditions": "那条指控重新提起并判败诉，升为「负面较多，需谨慎」。"}
```

- 总体结论只能选：存在重大负面，不建议合作 / 负面较多，需谨慎 / 有轻微负面，可正常合作 / 未发现负面事件 / 主体未确认，补X即可判断。
- 五类必须都写，`risk` 只能写 高 / 中 / 低；`items` 每类最多 8 条，`state` 写「已确认」或「还没核实」，`evidence` 只能填 data.json 里有的证据编号（来源链接和日期由套件带出）。没查到的一类只写 `summary` 和 `searched`。

查邮箱（S17 / S18）可写 `summary`；交易记录类（进口记录、出口记录、产品 / 原产国 / 目的国查询等）只写 `notes`，明细、条数和续页提示由套件列。

## 写法

- 用大白话：不写「口径 / 主体 / 反证 / MX 记录」这类词，写「怎么算的 / 查的是哪家公司 / 对他有利的情况 / 这个邮箱收不到信」。
- 不出分数或概率，不用「仅供参考」「无法判断」收尾。
- 页面上的状态说明（没查到、这次没查、只列了前几项、缺金额按票数排、缺的月份画虚框）由套件自动加，不用在 page.json 里重复。
