# 五项验证任务：只执行冻结输入

S23 验证WA、S25 验证单个邮箱、S26 验证批量邮箱、S82 验证关键人、S83 验证批量关键人使用 `type=verification`、`output_profile=O3`。验证Telegram暂不支持，如实告知。不得改71项可见提示词、名称或顺序。

## WhatsApp 与邮箱验证：快速通道（先判断）

验证 WhatsApp 号码或邮箱（单个或批量，S23/S25/S26）、用户没要 Excel 或其他文件时走这里；要文件或验证任职（S82/S83）走下文完整流程。快速通道不调 `plan_report`、`get_balance`、`get_render_spec`，不用 `task_run.py` 建日志，不写结果文件：

1. 按用户原文取号码或邮箱，保留原顺序；重复项只查一次，回复里标重复。号码作 JSON 字符串传，推荐 `{"numbers":["tel:+8613800000000"]}`，没有 `+` 或 `00` 国际前缀的先问国家码，不猜；明显不是邮箱的行不提交，回复里标格式错误。
2. 先用一句话说明费用，然后直接调用，不再等用户确认：WhatsApp 每个号码拿到确定结果扣 5 联系人点（已开通、未开通都收费），邮箱每封 2 联系人点。余额或授权不足由服务端拒绝，照原话转告。
3. `verify_whatsapp` 一次最多 100 个号码，服务端在一次调用内等到结果；仍返回 `meta.status=pending` 时，按 `retry_after` 只带 `request_id` 续查，不重发号码、不 refresh。`verify_email` 一次最多 10 封，超过就按原顺序每 10 封一批；pending 的按 `retry_after` 等待后只重发 pending 的那几封，已出结果的不重发。
4. 聊天里直接给结论，单个几行、多个一张表：号码或邮箱、结论（WhatsApp：已开通 / 未开通 / 无法判断 / 输入无效，附 `invalid_reason` 的修正说明；邮箱：可投递 / 不可投递 / 无法判断 / 被拒绝 / 仍在验证，附一次性、公共邮箱标记）、WhatsApp 的检查时间（换算北京时间）与是否复用历史结果、实扣点数（读每次响应的 `billing` 相加）。末尾一句边界：开通或可投递只说明号码注册了 WhatsApp 或邮箱能收信，不代表本人身份或营销许可。不加盲区表和自检清单。

## 请求与默认值

先把文件按用户指定列解析为数组，保留每个原始行（包括重复、空白与缺项），不从姓名/角色猜邮箱、号码、公司或职位。最小请求如下；可选字段删去时直接恢复默认，显式输入优先，不重复询问默认项：

```json
{"task":{"type":"verification","intent":"whatsapp","subject":{"numbers":["tel:+12025550123"]}}}
{"task":{"type":"verification","intent":"email","subject":{"email":"alex@example.com"}}}
{"task":{"type":"verification","intent":"batch_emails","subject":{"emails":["alex@example.com","bad","alex@example.com"]}}}
{"task":{"type":"verification","intent":"employment","subject":{"name":"Alex","company":"Example","title":"Buyer"}}}
{"task":{"type":"verification","intent":"batch_employment","subject":{"claims":[{"name":"Alex","company":"Example","title":"Buyer","profile_url":"https://www.linkedin.com/in/example"}]}}}
```

WhatsApp 可选 `constraints.refresh` 默认 false；任职可选 `constraints.employment_as_of` 默认 current，由规划器冻结具体日期；批量每行可显式提供 `employment_as_of`，优先于统一日期，同一人不同日期共享履历并逐项判断。公司官网可在人员主张里提供 `domain`，公司国家 `country` 保留为公司身份条件，不能拿人员所在地替代。已确认主页 `profile_url` 仍须记录本人明确确认，但无需再找20人。任职无默认3人总限额；工具批次≤5。单项默认 chat，批量 chat+xlsx（批量任务即使仅一行仍视为批量）；显式 `outputs.formats` 优先。输入错误不虚构必填主体，单人必填缺项澄清；批量缺项行保留未执行。

读取计划 `input_summary`，向用户说明总行数、重复、明显无效、待核验和初次最高预留。联系人点预算不是默认值：复用本次已授权的联系人点预算，付费任务无预算或超预算先合并确认；全无效输入只做零费预检，无须付费确认。开通授权、服务端余额仍独立核对。人员检索一页最多20人预留100联系人点，履历按实际人数预留；实扣只读公共 billing，不按结论或字段是否非空猜费用。

## 执行与续查

执行与续做按 SKILL.md 第 3 步写查询记录，同参成功不重跑；不要为重新渲染再调用已成功批次。

WhatsApp 首次按计划的规范文本提交一次。等待基于**响应接收时刻**加 retry_after；续查 params **仅** `{"request_id":"本任务首次响应给的32字符句柄"}`。句柄必须来源于对应号码作业，不能外来、换号、refresh或改句柄。首次响应丢失且没有句柄就停止，不重交号码；已知句柄的续查丢失可用同句柄继续同一作业。等待中实际0不释放首次预留，多次续查不重复预留。每次调用的实扣都记入查询记录；后续0费不能替之前未知的费用清零，未知费用先告诉用户。同作业所有有效终态的业务证据必须一致；状态、开通布尔、验证时间或历史复用矛盾时停止交付，后一次零费不能覆盖冲突。累计实际扣费还须不超过终态确定验证唯一号码数乘计划单价的上限；全未知不支持收费。低于上限只记实际账单，不补造消费。有有效终态后以它作业务证据，后续丢失、失败或迟到pending不把已确认结果降回待处理；没有终态时仍按实际等待或异常处理。其他作业的终态不能解消本作业。

邮箱无持久句柄。待定续查只传上次响应里 pending、故障或缺行的子集，保持原顺序，记下在已授权预算内继续的决定；按响应接收时间等待。每次续查可能再次扣普通点，先看剩余预算。终态（含unknown/rejected）复用；未知费用先告诉用户。大小写与+tag保留，只trim后精确去重。

任职先明确选人并记下确认依据：每项指定输入行号（从0起）和主页；用户给的主页记为用户提供，否则指向人员候选响应的真实行（调用编号、行号）。姓名和公司须与候选原值匹配；不自动认定同名、别名、集团子公司。公司国家主张须明确确认该公司所在国并记下所在国及依据，不使用候选人员地区作证明。没有确认证据就保留未执行。不同主张共享已确认人员主页的履历响应和费用，分别判定，不追加邮箱或电话。

邮箱或履历若只有调用失败、没有逐行响应，实际费用已知且明确确认失败后，只允许重试原完整批次，不能猜测成功或失败子集；仍须明确宿主决定、原身份与剩余预算。履历有逐行故障或缺行证据时，重试只发故障子集；成功空、未收录不可冒充故障重买。任职是/不确定/否与执行状态独立：仅精确公司职位和可比日期证据能确定，空履历/default false/其他雇主不证明离职，旧资料不证明当前。年月精度边界、未来日期、矛盾记录、不明确翻译均不确定；旧岗位结束但同岗重新入职须一起判断。

## 交付

每个原行保留：规范值、重复与共享查询映射、执行状态、结论、实际来源、证据行和实扣引用。WA含是否开通真/假/空、检查时间、历史复用、任务句柄；邮箱绿可投递/红不可投递/黄无法判断及格式有效/一次性/公共邮箱标志，有等待/拒绝/格式错分别标记；绿色不证明身份或营销许可。任职展示资料实际公司/职位（即使与主张不同）、本人确认依据，候选确认附保存的证据编号和响应行号；目标公司全部相关经历均展示职位、开始/结束/当前标志及抓取日，不能因职位不匹配就隐藏实际经历，也不能因此自动判否。邮箱只显示真实接收时间，不能编造提供方验证时间。

全无效输入可零费交付本地预检清单，来源明确用户输入；有效但没调用行是未执行/缺口，不能全批完成。等待中允许阶段结果，未知费用如实标未知。读取O3每种格式的get_render_spec后出成品；主表颜色真实标色且有文字，公式形态原输入保存为文本。交付前逐格回读核对；不要改数据凑结论。

## 新五项计划（verification-workflows/1）

新五项计划带内部自动步骤 verification_freeze，宿主无需操作；它不新增人工选择，不代表 contacts、email_verify 或 whatsapp_verify 已开通。仍按原业务步骤沟通。

响应缺有效 billing 时费用记未知，不能冒充费用已知或业务成功证明。真实 MCP 错误照原文记下；损坏的响应按未知处理，不补空 data 或零费用。邮箱和任职仍使用原业务规则和原字段，不能伪造履历或验证时间。查询到的邮箱、号码、人员履历和句柄只留在本任务工作目录，不进入日志或公开附表。
