# KOC 分销引擎 · KOC Distribution Engine

用在 5R 飞轮的 **R4 分销关**。这一关要回答两个问题：**钱怎么流**，以及**这笔生意到底赚不赚**。

先说一个必须让用户知道的事实：**只看直接归因，KOC 铺量在多数快消场景是不赚钱的。**
它的价值必须靠三块补齐 ——**增量（种草带来的搜索与自然成交）+ 内容复用（素材银行）+ 搜索承接**。
所以 **KOC 预算不该挂在单一的 CPS ROI 上考核**。这一点不讲清楚，方案迟早会被"ROI 不达标"砍掉。

## 什么时候用

- 要设计分销链路、定佣金率、算能不能赚钱；
- 要决定寄多少样、寄给谁、寄样预算怎么定；
- 要设计货盘（KOC 卖什么）；
- 要把 KOC 内容拿去投流（素材授权）；
- 要回答"为什么我 KOC 做了三个月，GMV 上不去"。

## 标准用法

### 一、先算能不能赚钱（不要先谈佣金率）

```bash
python3 scripts/koc_econ.py sample --json '{"C_goods":45,"C_ship":8,"AOV":129,"m":0.45,
  "c":0.20,"f":0.10,"rr":0.12,"C_ret":8,"r_pub":0.70,"r_qc":0.85,"O":2.5,
  "budget_sample":30000}' --text
```

输出：单篇有效内容成本、单笔净毛利、**盈亏平衡篇均订单数 O\***、直接归因 ROI、
有效出稿率敏感性、后置稿费的划算上限、可承受寄样量。

核心公式（口径见 references）：

```
C_sample   = 商品成本 + 寄样物流
r_eff      = 出稿率 × 合格率                       ← 决定成本的最关键变量
C_note_eff = C_sample / r_eff + 稿费 + 激励        （稿费后置，KOC 主流）
g          = (1−退货率)×客单价×(毛利率−佣金率−平台费率) − 退货率×逆向成本
O*         = C_note_eff / g                        ← 每篇内容至少要带来这么多单才回本
ROI_direct = 实际篇均订单数 O ÷ O*
```

> **有效出稿率对成本是倒数级敏感**：从 30% 提到 76%，单篇内容成本降约 60%。
> **履约机制的收益远大于议价。** 所以第一优先级永远是"稿费后置 + 履约条款 + 黑名单"，不是压价。

### 二、算可承受的最高佣金率

```bash
python3 scripts/koc_econ.py commission --json '{"C_goods":45,"C_ship":8,"AOV":129,"m":0.45,
  "f":0.02,"rr":0.10,"C_ret":8,"n_exp":1.5,"c":0.20,"tuanzhang_rate":0.05,
  "alliance_fee_on_promo":0.10,"category_band":[0.15,0.25]}' --text
```

输出 `c_max` 与「每 100 元 GMV 的钱去哪了」的完整拆解（COGS / 达人佣金 / 团长服务费 /
平台技术服务费 / 品牌留存）。

**决策规则**：
1. 用 `c_max` 算出理论上限；
2. 与类目常见区间取交集；
3. **若 `c_max` < 类目区间下限 → 这个品不适合做 CPS 型 KOC 铺量**，
   改成"按篇采买内容 + 授权复用"（内容买断）模式；
4. 新品冷启用"高佣 + 低单量"，成熟期切阶梯佣金，**把边际佣金给增量**。

### 三、阶梯佣金模拟

```bash
python3 scripts/koc_econ.py tier --json '{"mode":"marginal",
  "tiers":[{"from":0,"rate":0.10},{"from":3000,"rate":0.15},{"from":10000,"rate":0.20}]}' --text
```

用 `mode:"total"` 可以看全额跳档的**悬崖效应**——它会制造"刷单凑门槛"的动机，
也会让差一点的人直接放弃。**默认用超额累进（marginal）。**

### 四、货盘设计（KOC 卖什么）

| 类型 | 作用 | 定价与佣金 | 占比建议 |
|---|---|---|---|
| **引流款** | 撬第一单（尤其微信生态：72 小时内首单能把归因窗口从 3 天延到 30 天） | 低价、佣金可高 | 1–2 个 SKU |
| **利润款** | 真正赚钱的 | 主力价格带，佣金按 `c_max` 定 | 2–4 个 SKU |
| **形象款** | 撑住调性、方便出内容 | 高价、佣金低 | 1 个 SKU |
| **KOC 专供款** | 组合装/专属规格，避免与大促价打架、便于归因 | 独立货号 | 1–2 个 SKU |

> **专供款的隐藏价值**：有独立货号才能干净地算 KOC 的贡献，不会跟大促流量混在一起。

### 五、素材银行（KOC 分销真正的杠杆）

**一条 KOC 内容只发一次，成本是沉没的；被授权进入投流，边际成本就趋近授权费。**

必须在合作**开始前**谈好授权六维：**授权平台 / 期限 / 地域 / 用途 / 剪辑权限 / 转授权**。
发完再回头找人要授权，成功率极低且要重新谈价。三条链路与参数见 `@references/platform-links.md`。

复用摊薄后的单篇成本：`单篇有效内容成本 ÷ (1 + 复用深度)`。
**内容复用率（被二次使用 ≥1 次的内容占比）建议作为团队月度 KPI，红线 <10%。**

## 输出要求

- 佣金结构必须给出**每 100 元 GMV 的完整拆解**，且**必须包含平台技术服务费**（最常被漏掉）；
- 所有测算必须列出**输入假设**，并标注哪些是用户提供、哪些是行业基准假设；
- 结算规则必须写清 9 个字段（结算基数、有效订单定义、退款处理、券的承担、
  样品与坑位费计入、结算周期、归因窗口、异常订单排除、佣金追回）；
- 归因方式必须写清楚，并说明**为什么不能只看最后点击**。

## 禁止

- 不得建议刷单、虚假交易、空包、异常订单撬权重来"做起量"。
- 不得设计三级及以上分销、以拉人头计酬、或收取入门费的机制（先过 `koc-compliance-guard` 三闸）。
- 不得编造平台费率与达人报价。平台费率会变且**按账户分层**，签合同前必须让用户登录后台查本月适用费率。
- 不得用三方工具的预估数据做结算依据或对外承诺（千瓜官方自述抽样比例 10%–70%）。
