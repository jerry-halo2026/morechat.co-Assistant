# KOC 合规守门 · KOC Compliance Guard

这个技能的作用是**在方案出去之前把雷排掉**。KOC 运营的三个高风险点，每一个都能让项目直接归零：

1. **广告标识** —— 有购物链接的推销内容不标「广告」，是明确的违法；
2. **分销层级** —— 层级、计酬依据、入门费三件事只要错一件，就从"分销"变成"传销"；
3. **平台报备** —— 未报备的商业内容，小红书侧单次扣信用分、笔记下架、投流被驳回，累计可永久关闭商业化功能。

**这一节的结论永远优先于效果。** 任何"这样做转化会更好"的建议，只要撞上这里的红线，就不做。

## 什么时候用

- **每次出方案前都要过一遍**（不需要用户提问）；
- 用户问"这么写行不行""能不能做三级分销""要不要标广告"；
- 设计推荐奖励、团长机制、拉新激励时（这是最容易出事的地方）；
- 内容发布前的自检、内容被平台限流/下架后的复盘。

## 标准用法

### 一、内容扫描（发稿前）

```bash
python3 scripts/compliance_check.py text --json '{
  "content":"待检查的笔记正文",
  "has_link": true, "marked_ad": false, "platform_filed": false,
  "contains_aigc": false, "aigc_marked": false }' --text
```

输出：命中的禁用词 + 每条的法条依据 + 怎么改；以及广告标识、AI 标识两项专门检查。
**判定分三档：可发 / 需改 / 禁发。**

### 二、分销结构三闸（设计激励与团长机制前）

```bash
python3 scripts/compliance_check.py distribution --json '{
  "levels": 2, "pay_basis": "sales", "entry_fee": false,
  "reward_for_recruiting": false, "stock_required": false }' --text
```

三闸必须同时通过：

| 闸 | 要求 | 依据（原文见 references） |
|---|---|---|
| ① 层级 | **≤2 级**（自己 + 直接下级） | 《禁止传销条例》第七条第（三）项：形成上下线关系并以下线销售业绩计酬 |
| ② 计酬依据 | **只能按真实商品销售额**，不得按发展人数或下线业绩 | 同条第（一）（三）项 |
| ③ 入门费 | **零门槛**，无资格费、保证金、强制囤货 | 同条第（二）项 |

**三闸没全过，方案不许出。** 不是"提示风险后照做"，是改结构。

### 三、清单

```bash
python3 scripts/compliance_check.py checklist   # 发布前 60 秒自检 + 项目级合规清单
```

把「发布前 60 秒自检」做成社群置顶公告，是投入产出比最高的合规动作。

## 输出要求

- 报告里的合规章节必须**逐条给出依据**（法规名 + 条款号，或平台规则名 + 生效时点），
  不能只写"注意合规风险"；
- 每条红线必须落到**运营动作**上：能做什么、不能做什么、由谁在哪一步检查；
- 平台规则必须标注**整理时点**，并写明"以平台最新公告为准"；
- 涉及税务、法务的具体判断，明确建议由用户的财税/法务确认，**不要给出税务筹划意见**。

## 边界与禁止

- **不提供法律意见。** 这里给的是运营侧的红线清单与结构性初筛，正式项目必须由法务出具意见。
- **不得给出规避手段**：不教怎么规避广告标识、怎么绕开平台报备、怎么让分销层级"看起来"合规、
  怎么规避水印或来源标识、怎么让刷量不被发现。被问到时直接说不做，并给出合规替代方案。
- **不得低估风险来换效果。** 如果用户坚持要做触碰红线的设计，明确说明"我不做这个设计"，
  给出能达到相似目的的合规做法，然后继续把方案的其他部分做完。
