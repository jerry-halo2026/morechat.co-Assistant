# 持续学习与原创升级机制

> 版本：v1.19.25 新增｜单一事实源：agent.md 能力 11 与 SKILL.md「持续学习与原创升级机制」章节与本文件措辞必须一致，改其一必同步其余。

## 一、机制目标

保证专家包每次升级都来自「拉取全网当前质量最高的产品方法论 → 分析学习 → 原创设计 → 落地验证」，杜绝换皮式重复交付（仅改标题/措辞/顺序不算升级）。

## 二、升级前置：方法论学习（每轮升级必做）

1. **拉取**：升级前用搜索拉取 ≥3 个独立来源的当前高质量方法论，覆盖目标方向的最新实践与趋势（优先权威/专业来源：行业社区、官方文档、专家手册、最新出版方法论）
2. **消化**：识别可落地的模块（框架/清单/模板/口径/流程），逐条标注来源，但**只借鉴思路、不复制原文**，全部用自己的语言原创改写
3. **提炼**：输出「学习收获 → 候选升级点」对照，明确每个升级点解决什么问题、对应现有能力的哪个缺口

## 三、原创落地门槛（非换皮判定：至少满足 2 项，且逐项可被断言验证）

| 增量类型 | 门槛 | 验证方式 |
|----------|------|----------|
| 能力增量 | 新增 ≥1 个能力或子能力（如本轮能力 9/10/11） | 回归断言检查能力标题与关键要点 |
| 模板增量 | 新增 ≥1 类场景模板或专项清单 | 回归断言检查模板锚点 |
| 语料/口径增量 | 新增 ≥3 条 RC 评审反馈或 ≥3 项指标口径 | 回归断言检查编号与措辞 |
| 演练增量 | 新增 ≥1 份演练 PRD 并纳入路由/迭代闭环 | 回归断言检查演练命中与闭环落点 |

不满足门槛时不得升级发布；满足门槛但升级点无断言覆盖的，须补断言后发布。

## 四、禁止换皮红线

- 禁止仅改版本号/标题/措辞/章节顺序后重复交付
- 禁止把已有能力改名重排冒充新增
- 每次交付的变更说明必须列出「实质增量」清单（能力/模板/语料/口径/演练/机制），无实质增量不发版

## 五、回归防线

- 每个升级点的断言固化进校验脚本（package_and_validate.py 或 _verify_*.py），纳入一键回归
- 机制本身纳入回归：本资产存在、agent/SKILL 含机制章节、非换皮门槛描述齐全
- 升级后全量回归 12 步全绿 + 官方校验通过方可发布

## 六、版本与沿革

- 每次升级更新 plugin.json 版本、README 版本历史、演练案例集沿革（三处同步，断言校验）
- 升级点与学习来源记录进 README 变更行，保持可追溯

> 合规声明：本机制为产品专家包工作方法沉淀，内容全部原创撰写，不抄袭、不侵权、不踩红线；外部方法论仅作思路参考，引用须注明来源。
