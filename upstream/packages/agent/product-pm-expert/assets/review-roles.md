# 产品经理专家多角色评审关注点库

> 配套资产：与 agent.md「能力 6：需求风险评估」的多角色联合评审小节保持一致（单一事实源），改其一必同步其余。
> 用途：按需求类型选择评审视角，联合评审时逐角色对照，覆盖单视角盲区（研发看可行性、测试看可测性、资金看安全性）。

## 使用方式

1. **选视角**：资金类需求必含资金视角；依赖/性能重必含研发视角；交互/边界多必含测试视角；默认含产品视角（评审自查 8 项）
2. **独立评审**：每个角色按本库关注点独立评审，输出本角色发现清单（编号/发现/等级/建议）
3. **联合汇总**：全部角色发现并入联合评审表，冲突项按裁决序处理
4. **回归**：`_verify_roles.py` 自动核验角色库与演练产物匹配，纳入一键回归

## 一、研发视角（技术可行性）

| 编号 | 关注点 | 评审问法 |
|------|--------|----------|
| DEV-01 | 接口契约与字段定义 | 接口入参/出参/错误码是否定义齐全？契约变更是否兼容旧版？ |
| DEV-02 | 数据模型与存储 | 数据模型是否支持扩展？金额字段类型（分/Decimal）？索引与查询路径合理？ |
| DEV-03 | 状态机可实施性 | 状态迁移是否有边界？并发下状态一致性如何保证？ |
| DEV-04 | 幂等实现可行性 | 幂等键存储与去重方案是否可行？重试窗口与幂等冲突处理？ |
| DEV-05 | 性能与容量 | P95 目标是否可达？峰值容量是否估算？慢查询/热点键风险？ |
| DEV-06 | 依赖就绪与技术债 | 依赖是否三档分级 + 最晚就绪时限？是否引入技术债或临时方案？ |
| DEV-07 | 可观测性 | 日志/指标/告警是否覆盖关键路径？失败排查能否定位到单？ |
| DEV-08 | 安全与防刷 | 回调验签？防重放？接口防刷/限流？越权校验？ |

## 二、测试视角（可测性）

| 编号 | 关注点 | 评审问法 |
|------|--------|----------|
| TST-01 | 验收标准可测性 | 每条需求是否有可执行的 Given/When/Then？数值/行为可验证？ |
| TST-02 | 边界与异常用例 | 空/错/载/界四态、失败恢复、超时场景是否有用例？ |
| TST-03 | 资金用例覆盖 | 重复扣款/退款/对账差异/状态回跳是否有专项用例？ |
| TST-04 | 兼容性 | 多端/多版本/浏览器兼容范围是否定义？ |
| TST-05 | 灰度与回归 | 灰度分档验证项是否明确？回归影响面是否评估？ |
| TST-06 | 性能压测 | 压测指标与阈值是否定义（并发/吞吐/P95）？ |
| TST-07 | 测试数据与脱敏 | 测试数据是否可用？PII 是否脱敏？测试环境隔离？ |

## 三、资金视角（资金安全，资金类必查）

| 编号 | 关注点 | 评审问法 |
|------|--------|----------|
| FIN-01 | 幂等与重复入账 | 幂等键组成是否明确？重复请求是否防重？多扣是否原路退回？ |
| FIN-02 | 金额精度 | 金额是否以分/Decimal 存储计算？舍入规则是否统一？ |
| FIN-03 | 对账机制 | 对账周期/差异处理/轧差是否明确并留痕？ |
| FIN-04 | 退款口径 | 退款金额/手续费/原路退回/部分退款规则是否明确？ |
| FIN-05 | 资损监控 | 四类告警（重复支付/负金额/状态回跳/对账差异）是否配置？P0 是否及时触达？ |
| FIN-06 | 状态一致性 | 回调 + 主动查询双通道？状态回跳防护？ |
| FIN-07 | 风控联动 | 高风险交易是否拦截？拦截提示与申诉通道是否明确？ |
| FIN-08 | 税务与发票 | 发票流程/税务口径是否明确？含税/不含税标注？ |
| FIN-09 | 资金审计 | 资金流水是否可审计？留痕保留时长（≥180 天）？ |

## 四、联合评审流程与冲突裁决

### 流程

1. 产品视角评审自查（8 项）→ 2. 按需引入研发/测试/资金视角独立评审 → 3. 合并联合评审表 → 4. 冲突裁决 → 5. 修订落点跟踪 → 6. 评审记录留痕（第 N 轮通过）

### 冲突裁决序

**资金/安全底线 > 可测性 > 实现成本 > 体验**

- 资金/安全与实现成本冲突：优先资金/安全，成本让步（如续费重试次数以资金防重复为准）
- 可测性与实现成本冲突：优先可测性，成本让步（验收标准不可测不得上线）
- 体验与实现成本冲突：按影响面与排期综合裁决，记录理由
