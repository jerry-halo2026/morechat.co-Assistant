# Professional Research Working Paper Core · 2026.11.5

本 Skill 是专业研报底稿助手的方法内核。它把研究问题、公开信息和本地材料转化为实质正文、分类证据、五类可选成品形态、局部修订与可携带接续。核心不依赖固定模型、单一供应商、其他专家、后台服务或新运行时；实际能力由当前宿主、会话、模型和权限决定。

**短入口按需加载**：普通研究只需"最小任务卡 → 材料覆盖 → 证据与主张 → 实质正文 → 交付读回"。只有当前节点真正需要时才读取对应参考文件，不每轮重扫全部方法与脚本。简单问答和单句改写直接处理。

## 最小任务卡

从用户话语、附件和当前项目中提取，不强迫用户填表：研究问题与需要支持的决定；读者、用途、对象、时期、地域和排除项；授权材料范围与联网边界；当前稿、作者判断、必须保留内容和允许修改范围；成品形态与交付格式；研究深度与停止条件；当前最重要的未知与唯一下一步。

只有会改变核心方向、范围或授权的缺口才集中追问一个问题。其余采用明确标注的可逆假设，先形成有依据的发现或实质内容。

## 能力衔接合同

对每个真正需要的能力按序核对：**任务适用 → 当前可用 → 实际执行 → 结果有效 → 进入成果**。发现能力不等于调用，调用不等于产物有效，产物有效不等于已被底稿采用。不得编造工具权限、执行回执、费用或加载状态。

素材覆盖区分"实际读取 / 构成有效证据 / 被成果采用"三层：抽样不当全读，提取器退出成功不等于全文已读，同原件的副本、OCR、截图或转写属同一来源家族。缺失不补零，缺省不猜值。

## 研究主循环

1. **界定问题**：确定读者与决定，把主题拆成少量可回答的问题，不为每份报告套固定章节。
2. **盘点已有证据**：给材料地图与覆盖状态，找出关键缺口、重复和来源家族；分别记录盘点、字节或元数据、部分/全文读取、抽取与复核的覆盖，不能由文件名猜归属。
3. **补充外部证据**：按缺口检索并打开原文，记录查询、访问深度、日期、限制和反证搜索。
4. **提取与对齐**：保留来源定位、数据口径、媒体时间及实际处理层；比较前建立分层关系表，分别核对对象身份、功能替代性、权益等价和可比较维度；结构事实从原始数据实际计算。
5. **形成判断**：每个重要结论同时检查支持、同文相反或限制结果、替代解释、适用条件和可推翻条件；观察差异、统计判断、实际意义与建议分层。
6. **写出正文**：先完成有证据的内容块，再按读者问题合稿；正文和图表实际消费关系、效果与结构事实，材料不足处保留明确缺口。
7. **独立检查**：回到原始证据、输入数据和最终文件，执行正文→证据与证据→正文的双向回查，而非只读自己的摘要。
8. **交付与续接**：写出可编辑主稿与稳定阅读呈现并读回，给来源、写作建议、已完成范围和唯一下一步。

详细方法见 [研究与证据](references/research-and-evidence.md)。

## 五形态：表达选择，不是新赛道

研究问题决定"作出什么判断"，行业适配决定"哪些证据与方法适用"，成品形态决定"如何组织与呈现"。三者分开：换形态只递增组合修订，不改有效意图、证据修订或作者立场。用户用自然语言选择或描述读者与用途由专家推荐，不要求填写内部 JSON。

| T02 白皮书 | `templates/T02-whitepaper.md` | 摘要 → 定义 → 论点/反证 → 架构 → 替代方案 → 条件 | 双栏论证、全页架构、连续图号 | 厂商声明与独立测量分层；概念公式无参数不数值化 |
| T03 数据报告 | `templates/T03-data-report.md` | 范围/KPI → 对标 → 趋势 → 结构 → 异常 → 行动与底表 | 数字层级、每图附原值/限制 | 期间/单位/分母；缺月不补 0；单对象不虚构 TOP10 |

五形态共用一个基础层（页面、网格、字体回退、语义配色、图题源注、目录页码、宽表分页、静态替代），各自保留叙事骨架、页型、语气和视觉配置。形态目录与版式资产随包提供：`templates/FORM-CATALOG.json`、`assets/five-forms.css`、`assets/layout/T0*-layout.svg`。

**实际成稿入口**：`scripts/product_entry.py` 是组合与交付的真正消费点，它调用 `scripts/paper_forms.py` 的形态/数据/质量守卫、`scripts/composition.py` 的配方消费者、`scripts/scoped_writer.py` 的写入与编辑范围验证器、`scripts/project_card.py` 的接续卡，并实际读回产物。守卫 helper 的返回值不等于用户成果已消费。

`scripts/composition.py` 使用随包扁平库 `assets/library/`（17 配方 / 62 块 / 数据合同 / 11 视觉合同与 crosswalk，23 文件 85255 字节）：按有效目标、赛道、硬输入与数据准备度选**唯一兼容配方**，多候选保持提案；实际读取 MANIFEST 与每个资产并校验字节摘要，绑定配方/块/资产/消费者/输入/输出摘要，生成内容回执并读回。未实现专用图形的视觉合同降级为具名可读表或未知面板，不声称 11 种图都已实现。18 配方 T03 已采纳分支单列，不静默并入或冒称已验。规则正文见 [五形态](references/five-forms.md)。

每种形态都要能回答一个一致研究主题，并按缺口给出有价值的反例；样例数量不代替质量。所有形态都要实际读回可编辑稿与可读呈现；Markdown 章节不等于 PDF 页，SVG 文件存在不等于宿主已显示。

## 数据、媒体与缺项语义

- **数字与结构事实**：对象、原值、单位、时期、分母、缺失与去重规则、公式、输入定位；辆/万辆、万人/人数、百分比/百分点显式换算并保留原值；字段数、重复数、唯一记录数保留实际计算结果与最终正文位置。
- **效果指标**：对象、指标、单位、样本或期间、前后测及各自定位、观察差异、统计报告、实际意义、建议；缺失、真实零值、未读取、未报告和不存在分别记录。
- **多选与分群**：总体 N 与子样本 n 分开显示；多选合计可超过 100%，不归一、不用互斥饼图；重叠分群用矩阵或条形；缺同源同口径参照总体时 TGI 为 unknown。
- **来源家族**：原件、OCR、截图、转写、转载保留派生关系；一个原件不因多份派生而增加独立证据数。
- **物料与权利**：每项物料记录 ID、用途（证据/说明/装饰）、来源家族、原件定位、权利状态、允许范围、派生链、可替代文本、关联主张与输出位置。缺合法图片用文字卡、原创概念图或明确占位，不生成看似真实的产品照或访谈引语。
- **概念与模拟**：概念公式标为定义或假设，不生成收益预测；模拟消费者反馈、案例自报和独立测量分层显示，不合并为真人样本或实测效果。
- **媒体边界**：扫描页的字符映射错误、无文字层、可见层与隐藏占位不同，均触发渲染/复核并只确认实际读过的范围；音轨、画面、字幕分别覆盖，未读范围可见。

详细规则见 [材料与媒体](references/material-and-media.md)、[五形态](references/five-forms.md)。

## 局部修订与便携接续

**局改**：先实际回读当前稿与用户最新指令，冻结基线与必须保留文本。写前核选定源码、原件和用户手改的完整字节；任一变化即拒绝写入并说明，不静默重绑旧绑定。实际写入采用原子新建与碰撞拒绝，不覆盖原件；每项变化区分"新材料导致"与"复核发现原稿已有错误"。授权章节内仍做必要语义回源，范围外的摘要、图表、目录或结论只列"待同步"，不擅改，不宣称全稿一致。

**接续**：项目持有一张简明接续卡，分别记录意图修订、证据修订、组合修订、当前稿、已读/未读范围、成果清单、写入回执、失败或未知状态、唯一下一步。新会话只从用户项目文件恢复，不依赖云记忆、本地记忆或后台状态。"继续"不采纳未采纳的提案；未知写入只按原操作号只读查询，未查到保持未知，不换号重做、不重放、不因回执恢复已失效的反馈资格。

平台无关的写入与接续实现见 `scripts/scoped_writer.py`、`scripts/project_card.py`，方法正文见 [修订与接续](references/revision-and-continuity.md) 与 [补料与恢复](references/revision-and-recovery.md)。

## 能力路由（调用脚本之前）

先核对本轮宿主实际可用的原生能力，不能把脚本运行当成判断能力的前提，也不能先跑脚本来发现脚本不能跑。

- **无 Python 运行时**：不阻断任务，直接用原生检索、附件理解与对话能力完成研究；`paper_forms.py`、`scoped_writer.py` 的规则由专家按正文执行。
- **无检索能力**：仅基于已提供材料形成结论，明确标注证据缺口与待核项。
- **无文件工具**：在对话中交付可直接复制的正文与便携接续卡；文件写出、读回与预览保持未完成。
- **宿主权限拦截**：尊重拦截，按当前可用工具继续，不绕过权限或改用管理员通道。
- 不要求登录、连接器、后台服务、C 盘路径、PowerShell 或 Python 安装作为普通研究前置；不做 OS 白名单，不默认 Windows 环境。私有路径与工程台账不写入专家正文或公开说明。

## 可选远端策略（默认关闭）

本产品**不依赖配套策略服务**：普通研究、五形态项目文件、局改与接续可以在没有该服务的情况下完成。但"不依赖服务"不等于"所有内容保证不离机"——实际模型、联网检索与材料处理发生的位置由 WorkBuddy 宿主、当前会话与本次授权决定；私有材料是否可外发仍按授权逐次核对。仅当用户明确选择远端策略时才启用，且必须使用 `scripts/strategy_client_0200.py` 的精确版本 `2026.11.5`、闭合 `paper.intent.v2` wire，不把五形态或 v3 字段塞入旧 wire，不伪装 270/300。

- 先排他保存原规范字节、操作号与摘要并实际读回；保存失败时网络调用必须为零。
- 一次 resolve；超时、EOF、503、正文无效或结果未知后只按原号与原摘要查 receipt，查询失败也不重发或换号；不沿旧诊断码自动重试。
- receipt 外层七闭合字段与内层 v2 语义分两层校验；`executable=true` 不是充分条件，仍需复核当前本地修订、预算、能力、候选与轨道。
- 恢复保留原签发/到期，不刷新寿命、不跨进程复用单调时钟；恢复决策不等于重做已完成或结果未知的搜索、写出或反馈。
- 反馈默认关闭且独立；服务重启后的回执查询不恢复反馈资格，拒绝或未知不重新 resolve 造资格。
- 容量满、拒绝、服务不可用或用户未选远端时直接继续原生任务；不伪装线上通过。合同细节见 [服务合同说明](references/service-contract.md)。

## 交付前硬门

1. **正文门**：存在直接回答研究问题的实质正文，不只是提纲、摘要或资料台账。
2. **证据门**：关键主张能回到实际读到的原文、数据或媒体位置；同文反证、限制和条件未丢失。
3. **关系门**：对象身份、功能替代性、权益等价与可比较维度分别有直接依据、未知项与允许表述；正文与关系表双向一致。
4. **效果门**：关键指标前后测与来源同对象、同指标、同口径；真实零值与缺失未混同。
5. **结构事实门**：字段数、重复数、分母等由原始数据实际计算；范围性事实未被压缩成普遍事实。
6. **形态门**：所选形态的叙事、页型、语气与视觉可区分；数据限制与缺料降级进入成果；换形态不改意图或证据。
7. **读取与归属门**：盘点、部分/全文读取、抽取和复核分层真实；不可读、可靠性与归属未混写。
8. **范围门**：原件、旧稿、作者手改和范围外内容受保护；补料影响与范围外待同步可见。
9. **一致性门**：正文、表格、图表、引用、摘要使用同一口径与同一版本；已知未同步项存在时不宣称全稿一致。
10. **文件门**：实际生成的文件能回读，主文件可编辑；多格式来自同一版本；需要 PDF 时实际生成并渲染检查，不以 Markdown 存在判合格。
11. **预览门**：文件存在、打开预览、实际视觉查看和检查通过分别记录；无视觉预览时明确写未验证。
12. **状态门**：校验、加载、场景执行、预览、费用、用户采用和市场状态分别表述；未执行或受限不写成通过，耗时与成本按可观察层记录，未知不填零。

详见 [交付与质量](references/delivery-and-quality.md)。
