# 抖音视频情报采集与深度分析（douyin-video-intel）

> **一句话定位**：给一条抖音链接 + 后台数据 → 输出「公开数据 + 后台全量数据 + 口播文案 + 运营诊断 + 对标拆解 + 综合评估」六件套。

## 触发条件

用户消息中出现**抖音视频链接/分享口令/aweme_id**，且意图属于以下任一：

| 意图 | 用户可能怎么说 |
|------|--------------|
| 要数据 | "这条视频数据怎么样""帮我看下点赞评论""这个视频的综合数据""分析一下这条视频的数据" |
| 要文案 | "提取这条视频的文案""口播稿扒下来""这个视频说了啥" |
| 要拆解 | "拆解一下这条爆款""帮我对标分析""这条为什么能火" |
| 要综合评估 | "帮我全面分析这条视频""结合数据看看这条视频怎么样""给个综合评分和优化建议" |
| 要仿写 | "按这个结构给我写一条""仿写一版" |

> 只要给了抖音链接，**默认执行「公开数据 + 后台数据(如有) + 文案 + 诊断 + 对标拆解 + 综合评估」全流程**。用户明确只要其中一项时才裁剪。

## 标准工作流

### 步骤 1 · 抓公开数据（必做，秒级）

```bash
python <skill>/scripts/douyin_video_data.py "<用户给的原始链接或分享口令>" \
  --json ./douyin_data.json --md ./douyin_data.md
```

- 输入可以直接把用户粘贴的**整段分享口令原文**丢进去，脚本自己捞链接、跟 302、解 aweme_id。
- 成功时 stdout 直接输出 Markdown 数据卡，可直接引用给用户。
- 失败退出码含义：`2` 输入无法识别 / `3` 网络抓取失败 / `4` 作品非公开（已被删除、仅自己可见、审核中）。
  - **退出码 4 必须如实告诉用户"这条作品非公开，任何免登录工具都拿不到"**，不要谎称工具故障，也不要换平台重试。

### 步骤 1.5 · 接入创作者后台全量数据（核心增强，强烈推荐）

> **为什么需要这一步**：抖音公开接口的 `play_count` 恒为 0，完播率/跳出率/流量来源等核心指标**仅创作者后台可见**。没有这些数据只能做结构性比率诊断（以点赞为基数），无法做完整的漏斗分析和流量质量判断。

##### 模块 B · 内容吸引力指标

| 字段 | 含义 | 黄金标准线 | 合格线 | 解读规则 |
|------|------|-----------|--------|---------|
| `完播率` | 完整播放人数 / 播放量 | ≥ 25% | ≥ 15% | < 10% 说明开头或中间严重流失 |
| `平均播放时长` | 人均观看秒数 | > 时长×50% | > 时长×30% | 短于 5 秒说明钩子失效 |
| `2s跳出率` | 2秒内划走比例 | ≤ 35% | ≤ 45% | > 50% 开头致命问题 |
| `5s完播率` | 播放超过5秒的比例 | ≥ 45% | ≥ 30% | 前5秒留不住人=钩子+承接双失败 |
| `平均播放占比` | 平均观看时长 / 视频总时长 | ≥ 40% | ≥ 25% | 反映内容整体粘性 |

> 来源：流量分析 Tab → 内容吸引力板块

##### 模块 C · 观众参与度指标

| 字段 | 计算公式 | 黄金标准线 | 合格线 | 业务含义 |
|------|---------|-----------|--------|---------|
| `点赞率` | 点赞量 / 播放量 | 2.5%~4% | ≥ 1.5% | 内容认可度 |
| `评论率` | 评论量 / 播放量 | 1%~2% | ≥ 0.8% | 讨论激发能力 |
| `分享率` | 分享量 / 播放量 | 0.8%~1.5% | ≥ 0.4% | 传播裂变能力 |
| `收藏率` | 收藏量 / 播放量 | 0.8%~1.5% | ≥ 0.4% | 干货价值/复看意愿 |
| `弹幕量` | 弹幕绝对值 | — | — | 实时互动热度（非所有品类适用） |
| `不感兴趣率` | 标记不感兴趣的比例 | ≤ 0.5% | ≤ 2% | > 3% 说明内容冒犯或误推 |

> 来源：流量分析 Tab → 观众参与度板块

##### 模块 D · 流量来源构成

| 字段 | 含义 | 健康参考 | 解读 |
|------|------|---------|------|
| `推荐页占比` | 推荐算法分发占比 | **≥ 80%** 为健康 | 主力来源，< 70% 说明未被大池接纳 |
| `个人主页占比` | 从主页点击进入占比 | 5%~15% | 过高说明吃老粉，破圈能力弱 |
| `朋友页占比` | 好友分享页来源 | 1%~5% | 社交传播指标 |
| `同城页占比` | 同城频道推荐 | 1%~5% | 本地生活类应关注此指标 |
| `消息页占比` | 消息通知触达 | 0.5%~3% | 粉丝召回效果 |
| `搜索页占比` | 搜索结果进入 | 越高越好 | SEO 效果（如有） |
| `其他来源` | 其余入口 | — | 关注异常波动 |

**每个来源还需记录「对比7日」变化趋势**（如 +3.1% / -0.5%），用于判断流量走势：
- 推荐页占比**上升** → 内容被算法持续加温 ✅
- 推荐页占比**下降** + 个人主页**上升** → 在吃老粉，新客获取衰减 ⚠️
- 同城页占比较高（本地生活类）→ 地域标签生效 ✅

> 来源：流量分析 Tab → 流量来源板块

##### 模块 E · 额外流量与搜索

| 字段 | 含义 | 解读 |
|------|------|------|
| `平台扶持流量` | 平台额外激励播放次数 | 反映内容是否被平台青睐（如热点活动扶持） |
| `搜索关键词` | 用户通过哪些搜索词找到该视频 | 空 = 无搜索流量；有 = SEO 生效，可复用关键词 |

> 来源：流量分析 Tab 底部

### 步骤 2 · 提取口播文案（默认做）

```bash
C:/Users/Administrator/.workbuddy/binaries/python/envs/douyin-asr/Scripts/python.exe \
  <skill>/scripts/douyin_transcript.py "<原始链接>" --model medium --outdir ./
```

- 默认 `medium` 模型（中文准确率与速度的最佳平衡）。视频很长或用户赶时间时用 `--model small`。
- **当前环境已预置 medium 模型缓存**（位于 `~/.cache/huggingface`），首次运行通常无需下载；若缓存缺失会自动走国内镜像 `HF_ENDPOINT=https://hf-mirror.com` 下载（medium 约 1.5GB），此时应提前告知用户"首次需下载模型，之后走本地缓存"，不要让用户以为卡死。
- 已开启 `condition_on_previous_text=False` + `no_speech_threshold=0.8`：**纯音乐 / 文字幻灯片 / 无语音音轨**的作品会返回**空逐字稿并给出提示**，不会编造内容（见下方排查表）。
- 产物：`{标题}_{时间戳}.txt`（纯逐字稿）、`.srt`（字幕）、`.json`（带时间轴）。
- 脚本**不做任何润色**，原始转写从 stdout 返回，由你来整理。

**你对逐字稿的整理边界：**

| 允许 | 禁止 |
|------|------|
| ✅ 补标点、分段 | ❌ 删减内容 |
| ✅ 修正 ASR 明显错字（尤其品牌名、专业术语） | ❌ 改写、概括、缩写 |
| ✅ 标注 `[听不清]` | ❌ 添加原视频没有的信息 |

> 纯图文作品没有音轨，脚本会报错退出，此时只交付数据 + 图文文案（`title_desc`）。

### 步骤 3 · 结构性比率诊断

数据脚本已自动算好并写进 `derived` 字段，你负责**解读而不是复述**。

⚠️ **关于播放量的铁律**：抖音公开接口的 `play_count` **恒为 0**，这是平台设计，不是抓取失败。因此**点赞率、完播率、5 秒完播、2 秒跳出这些以播放量为分母的指标一律算不出来**。
- 绝不能编造播放量或倒推播放量。
- **如果用户提供了后台数据（步骤 1.5），则以用户提供的后台数据为准**，计算完整比率。
- 如果用户未提供后台数据，则只交付不依赖播放量的**结构性比率**，详见 `references/metrics-caliber.md`。

### 步骤 4 · 对标拆解与仿写模板

拿到逐字稿后，按 `references/teardown-framework.md` 做：
1. **黄金六秒逐句拆**：0–2s 钩子、2–4s 痛点、4–6s 承接，标出用的是哪类钩子。
2. **2113544 结构映射**：把逐字稿切成 2 秒钩子 / 1 痛点 / 1 方案 / 3 卖点 / 5 秒信任 / 4 互动 / 4 转化，缺哪段就点出来。
3. **数据 × 结构交叉归因**：把步骤 3 的比率异常对上结构缺口（如收藏率低 ↔ 缺"3 卖点"的清单化表达）。**如果有后台数据（步骤 1.5），此处用后台数据的完整比率做归因，比结构性比率更精准。**
4. **产出仿写模板**：把结构抽象成填空模板，用户换行业词就能用。

### 步骤 5 · 综合分析与评估（★ 新增核心步骤）

> **触发条件**：用户提供了后台数据（步骤 1.5 有数据）时**必须执行**；未提供后台数据时跳过此步，在步骤 4 后直接结束。

本步骤将**后台全量数据 × 口播文案 × 结构拆解**三者融合，产出一份完整的综合评估报告。

#### 5.1 综合评分卡（百分制）

按以下维度打分，加权求总分：

| 维度 | 权重 | 评分依据 | 满分 |
|------|------|---------|------|
| **流量规模** | 15分 | 播放量级（S≥10万/A≥1万/B≥3千/C≥500/D<500） | 15 |
| **内容吸引力** | 25分 | 完播率(10) + 2s跳出率(8) + 5s完播率(7) | 25 |
| **互动质量** | 20分 | 点赞率(6) + 评论率(5) + 分享率(5) + 收藏率(4) | 20 |
| **流量健康度** | 15分 | 推荐流占比(8) + 流量来源多样性(4) + 不感兴趣率(3) | 15 |
| **文案结构** | 15��� | 黄金六秒(5) + 2113544完整度(6) + 钩子匹配度(4) | 15 |
| **传播潜力** | 10分 | 分享率(4) + 搜索关键词覆盖(3) + 平台扶持(3) | 10 |
| **总分** | **100分** | | **100** |

**评级标准**：
- **90+ 优秀**：各维度均衡或有突出亮点，可作标杆复制
- **75~89 良好**：主要指标达标，有 1~2 个短板需补强
- **60~74 及格**：基本合格但存在明显瓶颈，需针对性优化
- **60 以下 待改进**：多个核心指标不达标，建议重新策划或大幅改版

#### 5.2 漏斗流失分析

用后台数据画出完整的观看漏斗，定位流失最严重的环节：

```
播放量(100%)
  ↓ 2s跳出率流失 → 剩余：(100%-2s跳出率)
    ↓ 5s完播率留存 → 剩余：5s完播率对应比例
      ↓ 平均播放占比 → 剩余：平均看了多少内容
        ↓ 完播率 → 最终完整看完的比例
```

**每个流失节点给出**：
- 流失比例是否正常（对照黄金标准）
- 最可能的文案/内容原因（对应到逐字稿的具体位置）
- 优化建议

#### 5.3 数据 × 文案交叉归因表

| 数据异常 | 对应文案问题 | 定位（逐字稿时间戳） | 修复建议 |
|---------|------------|-------------------|---------|
| 2s跳出率高 | 开头钩子不够强 | 0~2s | 换钩子类型 |
| 5s完播率低 | 前5秒承接乏力 | 2~5s | 加悬念/利益前置 |
| 完播率低 | 中后段拖沓/无高潮 | 低谷时段 | 删减/加反转 |
| 点赞率低 | 缺共鸣点/金句 | 全篇扫描 | 加情绪触发句 |
| 评论率低 | 缺互动引导/争议点 | 末尾或争议位置 | 埋提问/可纠错细节 |
| 分享率低 | 缺社交货币/转发理由 | 结尾处 | 加"替我说话"/利他 |
| 收藏率低 | 缺干货/清单/工具属性 | 卖点部分 | 改清单化表达 |
| 推荐流占比低 | 标签漂移/内容不垂直 | 全篇 | 统一选题方向 |
| 不感兴趣率高 | 误推人群/标题党 | 标题/开头 | 校准标题承诺 |

#### 5.4 综合优化建议（按优先级排序）

根据以上全部分析，给出 **Top 5 优化动作**，每个包含：

1. **动作描述**：具体做什么
2. **预期收益**：预计改善哪个指标、幅度多少
3. **执行难度**：简单 / 中等 / 较高
4. **关联文案位置**：如果涉及文案修改，指出具体在哪改

## 常见问题排查

| 症状 | 原因 | 处理 |
|------|------|------|
| 退出码 4 `status_self_see` | 作者设为仅自己可见 / 已删除 | 如实告知用户，请其换公开作品 |
| 退出码 4 `SYSTEM_ITEM_NOT_EXIST` | ID 错误或作品已彻底删除 | 让用户重新复制分享链接 |
| 退出码 2 | 输入里没有可识别的链接 | 请用户把完整分享口令原文粘过来 |
| 粉丝数显示"未公开" | 分享页对部分账号不返回粉丝字段 | 如实标注未公开，别猜 |
| 无水印直链下载 403 | CDN 签名过期（约 24 小时） | 重跑步骤 1 拿新链接 |
| 首次转写很久没动静 | 在下载 Whisper 模型 | 提前告知用户；网络差可改 `--model small` |
| 转写出现繁体/夹杂英文 | Whisper 语言判定漂移 | 已设 `--language zh` + 中文 initial_prompt；仍异常时手动纠错 |
| 图文作品转写报错 | 无音轨 | 正常现象，只交付数据 + 图文文案 |
| 转写返回空 / 提示"未检测到人声" | 该作品是纯音乐、文字幻灯片或音轨缺失（no_speech_prob≥0.8） | 正常现象，不要当失败。直接交付「综合数据 + 图文文案(title_desc)」，并如实说明无口播可转 |
| 用户不愿提供后台数据 | 担心隐私/麻烦 | 尊重选择，按格式 A 交付，明确告知"有后台数据可以做更完整的漏斗分析" |

## 安全与合规边界

- 仅读取**抖音公开分享页**数据，不登录、不使用他人 Cookie、不发帖点赞评论、不修改任何账号。
- 用户提供的后台数据**仅用于本次分析**，不存储、不外传、不复用于其他用途。
- 无水印直链仅用于用户对自有/对标内容做学习分析，**提醒用户不得二次搬运发布**，搬运侵权且会被平台判重降权。
- 抓取频率自觉克制（脚本已内置重试退避），不做批量高频轮询。
- 数据仅供个人/团队内部分析，不对外分发。
